# Ch4: Single Cycle Processor (nanoLADA)

## 4.1 ภาพรวม

ISA บอกว่า CPU ต้องทำ**อะไร** ส่วนบทนี้ออกแบบ **datapath + control** ที่ทำงานนั้นจริง โดยเริ่มจากแบบที่ง่ายที่สุดคือ **single cycle**: **CPI = 1** (เริ่มคำสั่งใหม่ทุก cycle และทุก operation ของคำสั่งเป็น combinational logic) แต่ **cycle time ยาวมาก**

::: term
[Processor / CPU]{.abbr} [Central Processing Unit]{.full} [หน่วยประมวลผลกลาง]{.th}

- **คืออะไร:** ส่วนที่ execute คำสั่ง ประกอบด้วย **datapath** และ **control**
- **สัมพันธ์กับ:** การออกแบบ processor กำหนดค่า **CPI และ clock cycle time** (ส่วน IC ถูกกำหนดโดย ISA และ compiler)
:::

::: term
[Datapath]{.abbr} [เส้นทางข้อมูล]{.th}

- **คืออะไร:** ส่วนที่**เก็บ ย้าย และประมวลผลข้อมูล** ได้แก่ PC, register file, ALU, adder, extender, memory, MUX และสายเชื่อม
- **เปรียบเทียบ:** เป็น "ถนนและเครื่องจักร" ที่ข้อมูลวิ่งผ่าน
:::

::: term
[Control unit]{.abbr} [หน่วยควบคุม]{.th}

- **คืออะไร:** วงจรที่ **decode opcode** แล้วสร้าง **control signals** สั่งให้ datapath ทำงานตามคำสั่งนั้น
- **เปรียบเทียบ:** เป็น "ตำรวจจราจร" ที่บอกว่า MUX ตัวไหนเลือกทางไหน และใครได้เขียนข้อมูล
- **การ implement:** single cycle ใช้ **combinational logic, ROM หรือ PLA** ส่วน multi-cycle ใช้ **FSM หรือ microprogram**
:::

::: term
[RTL]{.abbr} [Register Transfer Language / Level]{.full} [ภาษาบรรยายการย้ายข้อมูลระหว่าง register]{.th}

- **คืออะไร:** สัญกรณ์ที่บอกว่าแต่ละคำสั่ง**ย้ายหรือแปลงข้อมูลระหว่าง storage อย่างไร** เช่น `R[rd] ← R[rs] + R[rt]; PC ← PC + 4`
- **ทำหน้าที่:** เป็น "spec" ของคำสั่ง ใช้หา requirement ของ datapath
- **Logical RTL vs Physical RTL (Ch5):** logical บอกผลรวมของทั้งคำสั่ง ส่วน physical บอกว่าแต่ละ cycle ทำอะไรบน register ภายในจริง
:::

## 4.2 Design Steps (5 ขั้น)

1. **Analyze ISA** หา datapath requirements: เขียนแต่ละคำสั่งเป็น **RTL** และระบุ storage elements
2. **Select components** ของ datapath และกำหนด **clocking methodology**
3. **Assemble datapath** ให้ครบ requirements โดย**เพิ่มทีละคำสั่ง**
4. **Analyze implementation** ของแต่ละคำสั่งเพื่อหาค่า **control points**
5. **Assemble control logic**

(สไลด์ชวนให้เทียบกับการออกแบบ software: requirement → design → implement)

## 4.3 nanoLADA ISA

::: term
[nanoLADA]{.abbr} [ISA ขนาดเล็กสำหรับใช้สอนในวิชา]{.th}

- **คืออะไร:** RISC แบบ **load-store, fixed-length 32 bits** มี 7 คำสั่ง และมี **3 formats**
- **ทำไมง่าย:** คำสั่งน้อย, fixed length และ **immediate กับ displacement ใช้ field เดียวกัน**
:::

| Format | Bits [31:26] | [25:21] | [20:16] | [15:11] | [10:0] |
|---|---|---|---|---|---|
| **R-type** | opcode (6) | rs (5) | rt (5) | rd (5) | reserved (11) |
| **I-type** | opcode (6) | rs (5) | rt (5) | immediate (16) | |
| **J-type** | opcode (6) | address/displacement (26) | | | |

::: term
[rs / rt / rd]{.abbr} [register source / register target / register destination]{.full}

- **rs:** register ต้นทางตัวแรก
- **rt:** register ต้นทางตัวที่สอง (R-type) หรือ**ปลายทาง** (I-type เช่น LW, ORI)
- **rd:** register ปลายทางของ R-type
- แต่ละ field มี **5 bits → อ้างได้ 32 registers**
:::

| คำสั่ง | Type | Opcode | RTL |
|---|---|---|---|
| `ORI rt, rs, imm` | I | 010000 | R[rt] ← R[rs] OR **zero_ext**(imm); PC ← PC + 4 |
| `ORUI rt, rs, imm` | I | 010001 | R[rt] ← R[rs] OR **zero_pad**(imm); PC ← PC + 4 |
| `ADD rd, rs, rt` | R | 000001 | R[rd] ← R[rs] + R[rt]; PC ← PC + 4 |
| `LW rt, imm(rs)` | I | 011000 | R[rt] ← MEM[R[rs] + **sign_ext**(imm)]; PC ← PC + 4 |
| `SW rt, imm(rs)` | I | 011100 | MEM[R[rs] + sign_ext(imm)] ← R[rt]; PC ← PC + 4 |
| `BEQ rs, rt, imm` | I | 100100 | if R[rs] = R[rt]: PC ← PC + 4 + sign_ext(imm) × 4 else PC ← PC + 4 |
| `JMP addr` | J | 110000 | PC ← addr × 4 |

## 4.4 Components ของ Datapath

::: term
[Register File]{.abbr} [ชุดรีจิสเตอร์]{.th}

- **คืออะไร:** กลุ่ม register ทั่วไป **32 ตัว × 32 bits** (address 5 bits)
- **Ports:** **อ่านได้ 2 port พร้อมกัน** (Read_A, Read_B) และ**เขียนได้ 1 port** (Write_Reg)
- **สร้างจาก:** **D flip-flop 32 × 32 ตัว, MUX** (เลือก register ที่จะอ่าน) และ **decoder** (เลือก register ที่จะเขียน)
- **สัมพันธ์กับ:** มี write port เดียว จึงเกิด **structural hazard** เมื่อ 2 คำสั่งต้อง WB พร้อมกันใน pipeline (Ch6)
:::

::: term
[Extender]{.abbr} [วงจรขยายบิต]{.th}

- **คืออะไร:** แปลง **immediate 16 bits เป็น 32 bits** มี 3 โหมด
- **Sign extend:** เติม 16 บิตบนด้วย **sign bit** ใช้กับ **LW, SW, BEQ** (offset ติดลบได้)
- **Zero extend:** เติม 16 บิตบนด้วย 0 → 0x0000_imm ใช้กับ **ORI**
- **Zero pad:** ให้ imm ไปอยู่ **16 บิตบน** แล้วเติม 0 ข้างล่าง → imm_0000 ใช้กับ **ORUI** (ทำงานคล้าย "load upper immediate")
:::

::: ex
สร้างค่าคงที่ 32 บิต 0x12345678 ด้วย 2 คำสั่ง:
- `ORUI r1, r0, #0x1234` → r1 = 0x12340000
- `ORI r1, r1, #0x5678` → r1 = **0x12345678**
:::

| Component | รายละเอียด |
|---|---|
| **PC** | register พิเศษเก็บ address ของคำสั่ง |
| **Adder (PC)** | คำนวณ PC + 4 โดย PC + 4 = {PC[31:2] + 1, 2'b00} → **ใช้ adder 30 bits ก็พอ** (2 บิตล่างเป็น 0 เสมอเพราะ word aligned) |
| **Memory** | ข้อมูลเข้าและออก 32 bits, address 32 bits, 1 read port, 1 write port (ใช้แยก instruction memory กับ data memory) |
| **ALU** | alu_ops: `00` S ← A + B, `01` S ← A OR B, `10` S ← A − B และมี **zero flag** (S = 0) |

::: term
[Fetch]{.abbr} [การดึงคำสั่ง]{.th}

- **คืออะไร:** ขั้นตอนอ่านคำสั่งจาก memory: **Instruction ← MEM[PC]; PC ← PC + 4**
- **หมายเหตุ:** RTL ของแต่ละคำสั่งมักไม่เขียนส่วนนี้ เพราะทุกคำสั่งทำเหมือนกัน
:::

## 4.5 Control Signals

| สัญญาณ | ค่า 0 | ค่า 1 | ควบคุมอะไร |
|---|---|---|---|
| `sel_pc` | PC ปกติ | addr × 4 (JMP) | MUX เลือก PC ถัดไป |
| `sel_addpc` | PC + 4 | PC + 4 + imm × 4 | MUX เลือกผลของ branch |
| `sel_wr` | **rd** | **rt** | MUX เลือก register ปลายทาง |
| `sel_b` | **R[rt]** | **imm** (extended) | MUX เลือก input B ของ ALU |
| `sel_data` | ผล ALU (S) | **ข้อมูลจาก Memory** | MUX เลือกข้อมูลที่จะเขียนลง register |
| `reg_wr` | ไม่เขียน | **เขียน register** | write enable ของ register file |
| `mem_wr` | ไม่เขียน | **เขียน memory** | write enable ของ data memory |
| `alu_ops` | — | — | 00 ADD, 01 OR, 10 SUB |

| คำสั่ง | sel_pc | sel_addpc | sel_wr | sel_b | sel_data | reg_wr | mem_wr | alu_ops |
|---|---|---|---|---|---|---|---|---|
| ORI | 0 | 0 | 1 | 1 | 0 | **1** | 0 | 01 |
| ORUI | 0 | 0 | 1 | 1 | 0 | **1** | 0 | 01 |
| ADD | 0 | 0 | **0** | **0** | 0 | **1** | 0 | 00 |
| LW | 0 | 0 | 1 | 1 | **1** | **1** | 0 | 00 |
| SW | 0 | 0 | x | 1 | x | 0 | **1** | 00 |
| BEQ | 0 | **= zero** | x | 0 | x | 0 | 0 | **10** |
| JMP | **1** | x | x | x | x | 0 | 0 | xx |

::: key
**ตรรกะเบื้องหลังตาราง** (ใช้สร้างตารางเองในห้องสอบได้):
- **R-type (ADD) เขียนลง rd** ส่วน **I-type เขียนลง rt** → sel_wr
- **คำสั่งที่ใช้ immediate** (ORI, ORUI, LW, SW) → sel_b = 1
- **LW เป็นคำสั่งเดียวที่เอาข้อมูลจาก memory** เขียนลง register → sel_data = 1
- **SW เป็นคำสั่งเดียวที่เขียน memory** และ **SW/BEQ/JMP ไม่เขียน register** → reg_wr = 0 ทำให้ sel_wr กับ sel_data เป็น **don't care (x)**
- **reg_wr และ mem_wr ห้ามเป็น x** เพราะจะเขียนทับข้อมูลผิด
- **BEQ ใช้ SUB** แล้วดู zero flag โดย sel_addpc = zero
:::

::: term
[Control implementation]{.abbr} [วิธีสร้างวงจรควบคุม]{.th}

- **Combinational logic:** สร้างสมการของแต่ละสัญญาณโดยตรง
- **ROM:** opcode เป็น address และ control signals เป็นข้อมูล
- **PLA:** G1–G7 = AND term ของ opcode แต่ละตัว (G1 = ORI, G2 = ORUI, G3 = ADD, G4 = LW, G5 = SW, G6 = BEQ, G7 = JMP) แล้ว OR รวม:
  - `sel_pc = G7`
  - `sel_addpc = G6·zero`
  - `sel_wr = G1 + G2 + G4`
  - `sel_b = G1 + G2 + G4 + G5`
  - `sel_data = G4`
  - `reg_wr = G1 + G2 + G3 + G4`
  - `mem_wr = G5`
:::

## 4.6 Critical Path

::: term
[Critical path]{.abbr} [เส้นทางวิกฤต / เส้นทางที่ช้าที่สุด]{.th}

- **คืออะไร:** path ของสัญญาณที่มี **delay รวมมากที่สุด** ในวงจร
- **ทำหน้าที่:** **กำหนด cycle time ขั้นต่ำ** (clock เร็วกว่านี้ไม่ได้ เพราะผลยังคำนวณไม่เสร็จ)
- **ใน single cycle:** **คำสั่งที่ยาวที่สุดคือ LW** เพราะใช้ทุกส่วน: fetch → decode → register → ALU → data memory → write back
:::

| ส่วน | (1) PC | Inst. MEM | (2) Control | (3) Register | (4) MUX | (5) ALU | (6) Data MEM | (7) MUX | รวม |
|---|---|---|---|---|---|---|---|---|---|
| ns | 10 | 40 | 40 | 20 | 10 | 60 | 40 | 10 | **230** |

::: ex
- **CPU time ของ 2 ล้านคำสั่ง** = 2 × 10⁶ × 1 × 230 ns = **0.46 s**
- **Clock สูงสุด** ≈ 1 / 230 ns ≈ **4.35 MHz**
:::

::: rel
Single cycle ทำให้ **ทุกคำสั่งต้องใช้เวลา 230 ns เท่ากับ LW** แม้ ADD จะไม่ใช้ data memory และ JMP ใช้แค่ fetch → **เสียเวลาเปล่า** นี่คือแรงจูงใจของ **multi-cycle (Ch5)** และ **pipeline (Ch6)**
:::

::: ex
**เพิ่มคำสั่ง scale `LD r1, (r2)[r3*4]`** (Exercise)
- ต้องเพิ่ม **shifter (<< 2)** ที่ R[rt] แล้วส่งเข้า ALU ไปบวกกับ R[rs]
- ใช้ผลเป็น address ของ data memory แล้วเขียนกลับ rd
- → เพิ่ม MUX และ control signal ใหม่ และ **critical path อาจยาวขึ้น** (มี shifter อยู่ใน path)
:::

# Ch5: Multiple Cycle Processor

## 5.1 ภาพรวม

::: term
[Multi-cycle processor]{.abbr} [โปรเซสเซอร์แบบหลายรอบสัญญาณนาฬิกา]{.th}

- **คืออะไร:** แบ่งการทำงานของคำสั่งเป็น**หลายขั้นตอนเล็ก ๆ** แต่ละขั้นใช้ **1 cycle สั้น ๆ** และคำสั่งต่างชนิดใช้จำนวน cycle ต่างกัน
- **ข้อดี:**
  - **cycle time สั้นลง**
  - **คำสั่งที่ง่ายกว่าข้ามขั้นที่ไม่ใช้ได้** (BEQ ใช้ 3 cycles, LW ใช้ 5 cycles)
  - **ใช้ hardware ร่วมกันได้** (ALU ตัวเดียว, memory ตัวเดียว) เพราะใช้คนละ cycle
- **ข้อเสีย:** CPI > 1 และ control ซับซ้อนกว่า (ต้องเป็น FSM)
:::

**ปัญหาของ single cycle:** cycle time ยาว เพราะ**ทุกคำสั่งต้องรอนานเท่าคำสั่งที่ช้าที่สุด**และติดอยู่กับ critical path นอกจากนี้ memory จริงก็ไม่ ideal (ใช้หลาย cycle)

**Physical rule ของ memory:** "fast memories are small, large memories are slow" (ในบทนี้สมมติว่ามี cache ทำให้ memory = 1 cycle ซึ่งจะกลับมาดูใน Ch8)

## 5.2 วิธีลด Cycle Time

::: term
[Datapath partitioning]{.abbr} [การแบ่งเส้นทางข้อมูล]{.th}

- **คืออะไร:** แบ่ง combinational dependency graph เป็นส่วน ๆ แล้ว**ใส่ intermediate register (latch) คั่น**
- **ทำหน้าที่:** ใช้ **หลาย cycle ที่เร็ว** แทน cycle เดียวที่ช้า
- **หลักการ:** **แต่ละส่วนควรใช้เวลาใกล้เคียงกัน (balanced)** เพราะ cycle time = เวลาของส่วนที่ยาวที่สุด
:::

::: term
[Intermediate registers]{.abbr} [รีจิสเตอร์คั่นกลาง (IR, REG_A, REG_B, REG_S, REG_M, REG_WR)]{.th}

- **IR (Instruction Register):** เก็บคำสั่งที่ fetch มา
- **REG_A / REG_B:** เก็บ operand ที่อ่านจาก register file หรือ extender
- **REG_S:** เก็บผลจาก ALU
- **REG_M:** เก็บข้อมูลที่จะ store (SW)
- **REG_WR:** เก็บข้อมูลที่จะเขียนกลับ register
- **ทำหน้าที่:** **พักค่าระหว่าง cycle** เพื่อให้ cycle ถัดไปใช้ต่อได้
:::

**5 ขั้นตอนของ multi-cycle:**

| ขั้น | ชื่อ | ทำอะไร |
|---|---|---|
| 1 | **Fetch** | IR ← MEM[PC]; PC ← PC + 4 |
| 2 | **Decode** | A ← R[rs]; B ← R[rt] หรือ ext(imm) |
| 3 | **Execute** | S ← A op B |
| 4 | **Memory** | Data ← MEM[S] หรือ MEM[S] ← M |
| 5 | **Write back** | R[rt/rd] ← Data หรือ S |

## 5.3 Physical RTL และจำนวน Cycle

| คำสั่ง | Cycles | Cycle 1 | Cycle 2 | Cycle 3 | Cycle 4 | Cycle 5 |
|---|---|---|---|---|---|---|
| ORI / ORUI | **4** | Fetch | A ← R[rs], B ← ext(imm) | S ← A OR B | R[rt] ← S | — |
| ADD | **4** | Fetch | A ← R[rs], B ← R[rt] | S ← A + B | R[rd] ← S | — |
| **LW** | **5** | Fetch | A ← R[rs], B ← sign_ext | S ← A + B | WR ← MEM[S] | R[rt] ← WR |
| SW | **4** | Fetch | A, B ← sign_ext, **M ← R[rt]** | S ← A + B | MEM[S] ← M | — |
| BEQ | **3** | Fetch | decode | if equal: PC ← PC + sign_ext(imm) × 4 | — | — |
| JMP | **3** | Fetch | decode | PC ← addr × 4 | — | — |

::: key
**LW 5 · ORI/ORUI/ADD/SW 4 · BEQ/JMP 3**

BEQ บวกแค่ imm × 4 (ไม่บวก 4 อีก) เพราะ **PC ถูกบวก 4 ไปแล้วตอน fetch**
:::

**Design steps ของ multi-cycle:** ISA analysis → Components → Assemble datapath → **Datapath + Logical RTs → Physical RTs** → Physical RTs → Control

**ปรับ datapath ได้อีก:** **ใช้ ALU คำนวณ PC + 4 แทน adder แยก** และ**รวม instruction memory กับ data memory เป็นตัวเดียว** (เพราะใช้คนละ cycle จึงไม่ชนกัน)

## 5.4 Control แบบ FSM และ Microprogram

::: term
[FSM control]{.abbr} [Finite State Machine]{.full} [หน่วยควบคุมแบบเครื่องสถานะ]{.th}

- **คืออะไร:** control ของ multi-cycle คือ **FSM** โดยแต่ละ state = 1 cycle และกำหนด control signals ของ cycle นั้น
- **States ในสไลด์:** **Fetch → Decode →** แตกไปตามคำสั่ง
  - ALU_Exec → WB (ORI, ORUI, ADD)
  - ADD_Calc → MEM → (WB) (LW/SW)
  - BEQ
  - JMP
  - แล้วกลับไป **Fetch**
- **Wait state:** ถ้า memory ไม่ ideal ต้องเพิ่ม state "wait for MEM"
- **Implement ได้ 2 แบบ:** **sequential circuit** (state assignment + next-state truth table) หรือ **microprogram**
:::

::: term
[Microprogram / Microcode]{.abbr} [ไมโครโปรแกรม]{.th}

- **คืออะไร:** implement control ด้วยการเก็บ control signals เป็น "**microinstructions**" ไว้ใน ROM แล้วมี **microsequencer** ไล่อ่านทีละตัว
- **ทำงานอย่างไร:** **1 macroinstruction (คำสั่ง assembly) → หลาย microinstructions** โดยแต่ละ microinstruction ระบุ control signals ของ 1 cycle และ **Map ROM** แปลง opcode เป็นจุดเริ่มต้นของ microcode
- **ข้อดี:** **เปลี่ยน microprogram (Map ROM) ได้ = ทำ ISA อื่นบน hardware เดิมได้**, ออกแบบ control ซับซ้อน (CISC) ได้ง่าย
- **สัมพันธ์กับ:** Intel แปลคำสั่ง CISC เป็น micro-ops (Post-RISC, Ch3)
:::

::: term
[Macroinstruction vs Microinstruction]{.abbr} [คำสั่งระดับ ISA vs คำสั่งควบคุมภายใน]{.th}

- **Macroinstruction:** คำสั่งที่ programmer เห็น (เป็นส่วนของ ISA)
- **Microinstruction:** คำสั่งภายใน CPU ระดับ control signals (เป็นส่วนของ organization)
- **ทำไมไม่เขียนโปรแกรมด้วย microinstruction โดยตรง (Exercise):**
  - microinstruction **ผูกกับ organization** เปลี่ยนรุ่น CPU แล้วโปรแกรม**ไม่ compatible**
  - microcode กว้างและยาวมาก code density แย่
  - **ISA เป็น abstraction ที่ทำให้ software portable**
:::

::: key
**Summary ของ Ch5:**
- single cycle มีข้อเสียคือ **cycle time ยาว**
- multi-cycle **แบ่งคำสั่งเป็นขั้นตอนเล็ก ๆ และทำ 1 ขั้นต่อ cycle**
- **แบ่ง datapath ให้แต่ละส่วนเท่า ๆ กัน** เพื่อลด cycle time
- **control คือ FSM**
- **CISC ทำให้ control ซับซ้อนกว่า**
- ยังไม่ได้รวม exception ไว้ใน design
:::

**นับ cycle (cycle time 40 ns):**

::: ex
**Single vs multi ใครเร็วกว่า:** 100 คำสั่ง
- single 45 ns/cycle → **4500 ns**
- multi 10 ns/cycle, CPI 4.6 → 100 × 4.6 × 10 = **4600 ns**
- → **multi-cycle ช้ากว่า** (ดูข้อนี้คู่กับ pipeline ใน Ch6)

::: ex
**Share ALU กับ PC adder:**
- ใส่ MUX ที่ input A ของ ALU (เลือก PC หรือ REG_A)
- ใส่ MUX ที่ input B (เลือกค่าคงที่ 4, REG_B หรือ imm × 4)
- ให้ cycle ของ Fetch ใช้ ALU คำนวณ PC + 4 ซึ่งทำได้เพราะ fetch ไม่ได้ใช้ ALU ทำอย่างอื่น
:::

::: ex
**รองรับ interrupt/exception:**
- เพิ่ม register **EPC** (Exception PC เก็บ PC ที่จะกลับไป)
- เพิ่ม register **Cause/Status**
- เพิ่ม state ใน FSM เพื่อตรวจ exception แล้วเปลี่ยน PC ไป handler (vector table / fixed entry)
- มีคำสั่ง return (IRET) ที่ restore PC และ status
:::

::: trap
- **Multi-cycle ไม่ได้เร็วกว่า single cycle เสมอ** เพราะ CPI สูงขึ้นและ register คั่นกลางมี overhead
- **CPI ของ multi-cycle ขึ้นกับ instruction mix** ต้องถ่วงด้วยความถี่ของแต่ละคำสั่ง
:::
