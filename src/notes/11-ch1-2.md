# Ch1: Introduction to Computer Architecture

## 1.1 ภาพรวม: วิชานี้เรียนอะไร

**Computer Architecture** มาจาก 2 คำ: **computer** และ **architecture** (โครงสร้างและแนวคิดการออกแบบ แบบเดียวกับสถาปัตยกรรมอาคาร) จึงเป็นการศึกษา**การออกแบบ (design) การวัด (measurement) และการประเมิน (evaluation)** ของคอมพิวเตอร์ ซึ่งมีหลายระดับของ abstraction:

| ระดับ (บนลงล่าง) | ตัวอย่าง |
|---|---|
| Application | โปรแกรมของผู้ใช้ |
| Operating System / Compiler | Linux, gcc |
| **Instruction Set Architecture** | ชุดคำสั่งเช่น x86, ARM, nanoLADA |
| Firmware | microcode |
| Instruction Set Processor / I/O system | CPU และระบบ I/O |
| **Datapath & Control** | ALU, register, MUX, control unit |
| Digital Design | gate, flip-flop |
| Circuit Design | transistor |
| Layout | วางวงจรบน silicon |

สไลด์บอกว่าเอกสารที่อธิบาย architecture หนึ่ง ๆ ควรมีอย่างน้อย **ISA, Computer Organization และ ABI**

::: term
[Abstraction]{.abbr} [การซ่อนรายละเอียด]{.th}

- **คืออะไร:** การแบ่งระบบเป็นชั้น โดยแต่ละชั้นเห็นเฉพาะ **interface** ของชั้นที่อยู่ติดกัน ไม่ต้องรู้รายละเอียดภายใน
- **ทำหน้าที่:** ทำให้ออกแบบระบบที่ซับซ้อนได้ (programmer ไม่ต้องรู้ว่า CPU มีกี่ pipeline stage)
- **สัมพันธ์กับ:** **ISA** คือ abstraction ที่สำคัญที่สุดของวิชา
:::

::: term
[ISA]{.abbr} [Instruction Set Architecture]{.full} [สถาปัตยกรรมชุดคำสั่ง]{.th}

- **คืออะไร:** **interface/สัญญาระหว่าง software กับ hardware** กำหนดว่า software สั่งให้ hardware ทำอะไรได้บ้าง
- **กำหนดอะไรบ้าง:** instructions (operators), operands, registers และ flags, การอ้างถึง memory (addressing), instruction format (การ encode เป็น binary) และ interrupt/exception handling
- **มองได้ 2 ทาง:**
  - **Abstraction of machine for software:** programmer เขียน C แล้ว compiler แปลเป็น binary โดยไม่ต้องรู้ hardware
  - **Abstraction of software for hardware:** **โปรแกรม 8088 รุ่นเก่ายังรันบน Core i7 ได้** (backward compatibility)
- **ตัวอย่าง:** x86, ARM, MIPS, nanoLADA (ISA ที่ใช้สอนในวิชา)
- **สัมพันธ์กับ:** Ch3 (ISA ทั้งบท) และกำหนดค่า IC กับ CPI ใน CPU time
:::

::: term
[Computer Organization]{.abbr} [การจัดองค์ประกอบคอมพิวเตอร์ / microarchitecture]{.th}

- **คืออะไร:** **โครงสร้างภายในที่ทำให้ ISA ทำงานได้จริง** ซึ่ง software มองไม่เห็นโดยตรง
- **ส่วนประกอบในสไลด์:** **ALU, Control Unit, Register, Bus, Memory subsystem, I/O subsystem** (keyboard, mouse, display, storage)
- **ตัวอย่างสำคัญ:** **Core i3, i5, i7 ใช้ ISA เดียวกันแต่ organization ต่างกัน** (จำนวน core, ขนาด cache, clock/Turbo Boost, Hyper-Threading)
- **สัมพันธ์กับ:** Ch4–Ch8 ทั้งหมดเป็นเรื่อง organization และกำหนดค่า CPI กับ T<sub>c</sub>
:::

| | ISA | Organization |
|---|---|---|
| ตอบคำถาม | เครื่องทำ**อะไร**ได้ | เครื่องทำมัน**อย่างไร** |
| ใครเห็น | programmer, compiler | hardware designer |
| เปลี่ยนแล้วต้อง recompile ไหม | **ต้อง** (binary เดิมอาจรันไม่ได้) | **ไม่ต้อง** (binary เดิมรันได้ อาจเร็วขึ้น) |

::: term
[ABI]{.abbr} [Application Binary Interface]{.full} [ส่วนต่อประสานระดับไบนารี]{.th}

- **คืออะไร:** ข้อตกลงระดับ binary ที่ทำให้โปรแกรมหรือ library ที่ compile แยกกันทำงานร่วมกันได้
- **กำหนดอะไรบ้าง:** **calling convention** (ส่ง parameter ทาง register หรือ stack, caller-save/callee-save), การคืนค่า, layout ของ stack frame, alignment ของข้อมูล และ system call
- **สัมพันธ์กับ:** subroutine และ parameter passing (Ch3) ซึ่ง ISA บอกว่ามีคำสั่ง CALL ส่วน ABI บอกว่าใช้มันอย่างไร
:::

::: term
[Register]{.abbr} [รีจิสเตอร์]{.th}

- **คืออะไร:** หน่วยเก็บข้อมูลขนาดเล็กที่สุดและเร็วที่สุด อยู่ใน CPU
- **ทำหน้าที่:** เป็น **temporary storage** เก็บ operand และผลลัพธ์ชั่วคราว เพื่อไม่ต้องไป memory ทุกครั้ง
- **เปรียบเทียบในสไลด์:** บวก 2 + 3 สมัยประถม → **จำ 2 ไว้ในหัว** (register) ชู 3 นิ้ว นับ 3, 4, 5 ได้ 5
- **สัมพันธ์กับ:** ยิ่งมี register มาก compiler ยิ่งเก็บตัวแปรได้มาก ทำให้เข้าถึง memory น้อยลง (แต่ต้องใช้บิตในคำสั่งเพื่อระบุ register มากขึ้น) และเป็นชั้นบนสุดของ memory hierarchy (Ch8)
:::

::: term
[Bus]{.abbr} [บัส]{.th}

- **คืออะไร:** ชุดสายสัญญาณที่ใช้ร่วมกันในการส่งข้อมูล, address และ control ระหว่างส่วนต่าง ๆ
- **สัมพันธ์กับ:** ความกว้างของ bus มีผลต่อ **endian performance** และ **miss penalty** ของ cache (block ใหญ่แต่ bus แคบจะช้า)
:::

## 1.2 Design Trade-offs และ Goals

::: term
[Trade-off]{.abbr} [การแลกเปลี่ยนเชิงออกแบบ]{.th}

- **คืออะไร:** การได้สิ่งหนึ่งโดยต้องเสียอีกสิ่งหนึ่ง ไม่มีการออกแบบไหนดีที่สุดทุกด้าน
- **คู่หลักในสไลด์:** **Cost vs Performance (vs Power)** ซึ่งต้องใช้ **modeling และ measurement** ในการตัดสินใจ
- **ตัวอย่างในวิชา:** single vs multi-cycle, block size ของ cache, write-back vs write-through, dynamic vs static scheduling, การให้ R-type ใช้ 5 stage
:::

**Design goals:** functional requirements (market/application driven), performance goals, cost constraints, power constraints

**เกี่ยวข้องทั้ง 3 ระดับ:** ISA (software interface), Organization (CPU internals, memory, buses), Hardware (logic design, packaging)

| Requirements | Software trends | Hardware trends |
|---|---|---|
| Application area: general purpose, scientific, commercial, multimedia | ต้องการ memory มากขึ้นประมาณ **2 เท่าต่อปี** (= address เพิ่ม 1 bit ต่อปี) | IC density, size, performance เพิ่มขึ้น |
| OS: memory management, protection, **context switching**, **interrupts** | ใช้ **compiler** มากขึ้น (ISA ออกแบบเพื่อ compiler ไม่ใช่ programmer) | **DRAM capacity 4 เท่าทุก 3 ปี** แต่ความเร็วเพิ่มช้า |
| Standards: IEEE floating-point, bus/I/O (PCI, USB) | optimization, scheduling | **Disk capacity 4 เท่าทุก 3 ปี** |
| Time to market, cost | | |

::: term
[Moore's Law]{.abbr} [กฎของมัวร์]{.th}

- **คืออะไร:** **ข้อสังเกต** (ไม่ใช่กฎทางฟิสิกส์) ของ **Gordon Moore** (co-founder ของ Fairchild Semiconductor และ CEO ของ Intel)
- **ใจความ:** **จำนวน transistor บน IC เพิ่มเป็น 2 เท่าประมาณทุก 2 ปี (18 เดือน)**
- **อย่าสับสน:** Moore's Law **ไม่ได้บอก**ว่า clock rate หรือ performance เพิ่มเป็น 2 เท่า
:::

::: term
[MIPS (หน่วยวัด)]{.abbr} [Millions of Instructions Per Second]{.full} [ล้านคำสั่งต่อวินาที]{.th}

- **คืออะไร:** จำนวนคำสั่งที่ทำได้ต่อวินาที (หน่วยล้าน)
- **ข้อควรระวัง:** สไลด์ระบุว่าเป็น "หน่วยเชิงการตลาด ไม่ใช่ performance จริง" (ดู Ch2)
- **อย่าสับสน:** กับ **MIPS ที่เป็นชื่อ ISA** (RISC processor)
- **สัมพันธ์กับ:** trend **Watts per MIPS** ดีขึ้นเรื่อย ๆ (ประหยัดพลังงานขึ้น)
:::

**Cost trends:** ราคา DRAM ลดลงประมาณ **40% ต่อปี** (เพราะ commoditization) ส่วนต้นทุนของ notebook เป็นแบบนี้: processor/circuit 25%, battery 25%, monitor 20%, storage 20%, RAM 10%, case 6%, video 5%, I/O/PCB 5%, keyboard/mouse 4% และมี margin 20–30%+

## 1.3 ทำไมต้องเรียน และ How to design

- Architecture ของ desktop/server **converged** แล้ว แต่ต้องเรียนเพราะ (1) เป็นวิศวกรคอมพิวเตอร์ (2) ต้อง**เลือก architecture ให้เหมาะกับงาน**ได้ (3) **เขียนโปรแกรมได้ดีขึ้น**
- **โปรแกรมเดียวกันเร็วไม่เท่ากัน**ได้ แม้จะใช้ algorithm, ภาษา และเครื่องเดียวกัน เพราะ data structure, compiler หรือ optimization ต่างกัน → "**Good knowledge of architecture means better program**"
  - ตัวอย่างในสไลด์: ใช้ `union` ที่รวม `unsigned short h[2]` กับ `unsigned int x` แล้วสั่ง `c.x = a.x + b.x` บวกเลข 16 บิตสองคู่ด้วยคำสั่งเดียว (คล้าย SIMD) ผลอาจต่างตาม compiler/OS
- **How to design:** เป็น**กระบวนการวนซ้ำ (iterative)** คือ Creativity → Design → **Cost/Performance Analysis** → แยก good / mediocre / bad ideas → ทำซ้ำ โดยใช้ **measurement and evaluation**

# Ch2: Performance: Measurement and Analysis

## 2.1 ภาพรวม

บทนี้ตอบคำถามว่า "เครื่องไหนเร็วกว่า เร็วกว่ากี่เท่า และควรปรับปรุงตรงไหน" เครื่องมือหลักมี 3 อย่าง: **Speedup**, **CPU Time equation** และ **Amdahl's Law**

::: term
[Performance]{.abbr} [สมรรถนะ]{.th}

- **คืออะไร:** ความเร็วในการทำงาน ซึ่ง**ขึ้นกับบริบท (relative)** และ**เป็นส่วนกลับของเวลา**
- **สูตร:** Performance = 1 / Execution Time → เวลาสั้น = performance สูง
:::

::: term
[Speedup]{.abbr} [อัตราเร่ง / เร็วขึ้นกี่เท่า]{.th}

- **คืออะไร:** อัตราส่วนบอกว่าเร็วขึ้นกี่เท่า
- **สูตร:** **Speedup = T<sub>old</sub> / T<sub>new</sub>** หรือ "X เร็วกว่า Y n เท่า" → **n = T<sub>Y</sub> / T<sub>X</sub>** = Perf<sub>X</sub> / Perf<sub>Y</sub>
- **อ่านค่า:** n > 1 = เร็วกว่า, n < 1 = ช้ากว่า
:::

::: ex
A ใช้ 20 s และ B ใช้ 25 s → A เร็วกว่า B = 25 / 20 = **1.25 เท่า**
:::

::: trap
- ห้ามตอบ 20/25 = 0.8 และอย่าสับสนกับ "เร็วขึ้น 20%" (ซึ่งคิดจาก (25 − 20)/25)
- ถ้าโจทย์ถาม "กี่เท่า" ให้ใช้ **เวลาของตัวช้า ÷ เวลาของตัวเร็ว**
:::

## 2.2 การวัด: Response Time vs Throughput

::: term
[Response Time / Latency]{.abbr} [เวลาตอบสนอง]{.th}

- **คืออะไร:** เวลาตั้งแต่เริ่มงาน**หนึ่งงาน**จนงานนั้นเสร็จ
- **มี 2 แบบ:**
  - **Elapsed time (wall-clock time):** เวลาจริงที่ผ่านไป รวมการรอ I/O และงานอื่น
  - **CPU time:** เวลาที่ CPU ทำงานให้โปรแกรมนี้จริง ไม่รวมเวลารอ
- **วัดอย่างไร:** คำสั่ง `time` ของ Unix ให้ค่า **real** (= elapsed), **user** (CPU time ใน user mode) และ **sys** (CPU time ใน kernel) ส่วน Windows ใช้ `ptime`
:::

::: term
[Throughput / Bandwidth]{.abbr} [ปริมาณงานต่อหน่วยเวลา]{.th}

- **คืออะไร:** จำนวนงานที่ทำเสร็จต่อหน่วยเวลา ซึ่งเป็น **parallelism ระดับ task**
- **สัมพันธ์กับ:** **pipelining เพิ่ม throughput แต่ไม่ลด latency** (Ch6)
:::

::: ex
- **Computer A** ทำ 5 งานพร้อมกันเสร็จใน 10 นาที → throughput **0.5 งาน/นาที**, response time **10 นาที**
- **Computer B** ทำทีละงาน งานละ 3 นาที → throughput **0.33 งาน/นาที**, response time **3 นาที**
- → **A มี throughput ดีกว่า แต่ B มี response time ดีกว่า**

**ส่งข้อมูล 20 TB:**
- ผ่าน fiber 1 Gb/s ใช้ 20 × 8 × 10¹² / 10⁹ = 160,000 s ≈ **44 ชั่วโมง** (สไลด์ปัดเป็น 40)
- **คนแบก HDD 1 TB จำนวน 20 ลูกเดินข้ามตึกใช้ 15 นาที**
- → **คนแบกมี throughput สูงกว่ามาก** แม้ fiber จะส่งข้อมูลชิ้นแรกถึงได้เร็วกว่า
:::

::: term
[FLOPS]{.abbr} [Floating-Point Operations Per Second]{.full} [จำนวนการคำนวณทศนิยมต่อวินาที]{.th}

- **คืออะไร:** หน่วยที่นิยมใช้กับงาน scientific และ GPU
- **ข้อควรระวัง:** เหมือน MIPS คือเป็นหน่วยเชิงการตลาด ไม่ได้สะท้อน performance ของงานจริงทุกงาน
:::

### ปัญหาในการวัด (Measurement Issues)

| ประเด็น | ความหมาย |
|---|---|
| **What to measure** | จะใช้โปรแกรมอะไรวัด |
| **Interference** | เครื่องว่างหรือมีงานอื่นรันอยู่ (multi-programmed) |
| **Reproducibility** | วัดซ้ำแล้วได้ผลเหมือนเดิมไหม |
| **Comparability** | A เก่งงาน multimedia แต่แย่งานอื่น ส่วน B กลับกัน แล้วตัวไหนดีกว่า? |

## 2.3 Benchmarks

::: term
[Benchmark]{.abbr} [โปรแกรมมาตรฐานสำหรับวัดผล]{.th}

- **คืออะไร:** ชุดโปรแกรมที่ใช้วัดและเปรียบเทียบ performance ซึ่งต้องเป็น**ชุดเดียวกัน (unified set)** จึงจะเทียบกันได้
:::

| ประเภท | ความหมาย | ตัวอย่าง |
|---|---|---|
| **Real** | ใช้ application จริง (มี script จำลองการใช้งานแบบ interactive/multi-user) | gcc, เกม |
| **Microbenchmark** | ใช้**ส่วนหนึ่ง**ของซอฟต์แวร์ | |
| **Kernel** | วัดเฉพาะบางแง่มุมของ performance | วง loop หลักของโปรแกรม |
| **Toy** | โปรแกรมเล็ก ๆ (นิยมในอดีต) | quicksort, merge sort |
| **Synthetic** | เขียนขึ้นให้**เลียนแบบพฤติกรรม**ของโปรแกรมจริง | **Whetstone** (floating point), **Dhrystone** (integer) |

::: term
[SPEC]{.abbr} [Standard Performance Evaluation Corporation]{.full} [องค์กรสร้าง benchmark มาตรฐาน]{.th}

- **คืออะไร:** องค์กร (SPEC.org) ที่ออก benchmark suites มาตรฐาน
- **ตัวอย่าง:** **SPEC CPU2017** (CPU), **SPECviewperf** (graphics), **SPECjbb2015** (Java virtual machine), **SPEC SFS2014** (file server)
:::

## 2.4 การรวมผลหลายโปรแกรม: Mean

| Mean | สูตร | ใช้เมื่อ |
|---|---|---|
| Arithmetic Mean (AM) | (ΣT<sub>i</sub>)/n | เวลา (มีหน่วย) โดยแต่ละโปรแกรมสำคัญเท่ากัน |
| **Weighted AM** | Σw<sub>i</sub>T<sub>i</sub> | เวลา โดยรู้สัดส่วน workload จริง |
| Harmonic Mean | n / Σ(1/r<sub>i</sub>) | rate (เช่น MIPS) |
| **Geometric Mean (GM)** | (Πr<sub>i</sub>)^(1/n) | **ratio ที่ไม่มีหน่วย (speedup, normalized time)** |

::: ex
ตัวอย่างในสไลด์ (เวลาเป็นวินาที):

| | A | B | C |
|---|---|---|---|
| Program 1 (80%) | 10 | 4 | 5 |
| Program 2 (20%) | 2 | 10 | 5 |
| Total | 12 | 14 | **10** |
| AM | 6 | 7 | **5** |
| Weighted AM | 0.8(10) + 0.2(2) = 8.4 | 0.8(4) + 0.2(10) = 5.2 | **5** |

- ถ้า workload เป็นตามสัดส่วนนี้ **C ดีที่สุด**
- แต่ถ้ารันแค่ Program 1 **B ดีที่สุด** → "เร็วที่สุด" ขึ้นกับ workload
:::

::: ex
Geometric mean ของ ratio:

| | A/B | A/C | C/B |
|---|---|---|---|
| Prog 1 | 2.5 | 2 | 1.25 |
| Prog 2 | 0.2 | 0.4 | 0.5 |
| **GM** | √0.5 = **0.71** | √0.8 = **0.89** | √0.625 = **0.79** |

ตรวจ: GM(A/B) ÷ GM(A/C) = 0.71 / 0.89 = 0.79 = GM(C/B) → **ผลสอดคล้องกันไม่ว่าจะใช้เครื่องไหนเป็น baseline**
:::

::: key
- **ข้อดีของ GM + speedup:** **ไม่ต้องสนใจขนาด workload** (ปรับจาก 5 s → 3 s มีค่าเท่ากับปรับจาก 500 s → 300 s)
- **ข้อเสีย:** **GM (และ speedup) ทำนาย performance หรือเวลาจริงไม่ได้**
:::

## 2.5 CPU Time Equation

::: term
[CPU Time]{.abbr} [เวลาที่ CPU ใช้ทำงาน]{.th}

- **คืออะไร:** เวลาที่ CPU ทำงานให้โปรแกรม (ถ้าไม่นับเวลารอ I/O)
- **สูตร:** **CPU Time = IC × CPI × T<sub>c</sub> = (IC × CPI) / Clock rate**
:::

::: term
[IC]{.abbr} [Instruction Count]{.full} [จำนวนคำสั่งที่ถูก execute]{.th}

- **คืออะไร:** จำนวนคำสั่ง**ที่รันจริง** (dynamic count) ไม่ใช่จำนวนบรรทัดของโค้ด เพราะ loop ทำให้คำสั่งเดิมรันหลายครั้ง
- **ขึ้นกับ:** **Program, ISA, Compiler**
:::

::: term
[CPI]{.abbr} [Clock (cycles) Per Instruction]{.full} [จำนวน clock cycle เฉลี่ยต่อคำสั่ง]{.th}

- **คืออะไร:** แต่ละคำสั่งใช้ cycle เฉลี่ยกี่ cycle
- **ขึ้นกับ:** **ISA และ CPU organization** (รวมถึง cache miss และ pipeline stall)
- **ค่าทั่วไป:** RISC มักมี CPI คงที่ (เช่น 1) และ single-cycle มี CPI = 1
- **Average CPI:** **CPI<sub>avg</sub> = Σ(CPI<sub>i</sub> × freq<sub>i</sub>)** โดย freq<sub>i</sub> คือสัดส่วนของจำนวนคำสั่ง class i
- **สัมพันธ์กับ:** **IPC (Instructions Per Cycle) = 1/CPI** ซึ่ง superscalar ทำให้ IPC > 1 (CPI < 1)
:::

::: term
[Clock rate / Cycle time (T<sub>c</sub>)]{.abbr} [ความถี่สัญญาณนาฬิกา / คาบเวลาหนึ่ง cycle]{.th}

- **คืออะไร:** clock rate มีหน่วย MHz หรือ GHz ส่วน **T<sub>c</sub> = 1 / clock rate** (1 GHz → 1 ns)
- **ขึ้นกับ:** **CPU organization (critical path) และ VLSI technology**
:::

| ตัวแปร | ขึ้นกับ | วิธีลด (Performance Improvement) |
|---|---|---|
| **IC** | Program, ISA, Compiler | redesign ISA, compiler optimization |
| **CPI** | ISA, Organization | redesign ISA, redesign organization (pipeline, cache) |
| **T<sub>c</sub>** | Organization, VLSI technology | redesign organization, transistor ที่เร็วขึ้น |

::: rel
ทั้ง 3 ตัวแปร**ดึงกันไปมา**:
- RISC ลด CPI และ T<sub>c</sub> แต่ IC เพิ่มขึ้น
- multi-cycle ลด T<sub>c</sub> แต่ CPI เพิ่มขึ้น
- VLIW ลด IC
- pipeline ลด CPI ที่มีผล
- cache miss เพิ่ม CPI

ดังนั้น**ห้ามดูตัวแปรเดียวแล้วสรุปว่าเร็วกว่า**
:::

::: ex
CPU 1 GHz รัน 2000 ล้านคำสั่งใน 20 s ถ้าเพิ่ม clock เป็น 2 GHz แต่ CPI แย่ลง 1.2 เท่า จะใช้เวลาเท่าไร?
1. CPI<sub>เดิม</sub> = (20 s × 10⁹ Hz) / (2000 × 10⁶) = **10**
2. CPI<sub>ใหม่</sub> = 10 × 1.2 = **12**
3. T<sub>ใหม่</sub> = (2000 × 10⁶ × 12) / (2 × 10⁹) = **12 s** (เร็วขึ้น 20/12 = 1.67 เท่า ไม่ใช่ 2 เท่า)
:::

### MIPS เป็นหน่วยวัดที่ไม่ดี

::: formula
MIPS = IC / (T × 10⁶) = Clock rate / (CPI × 10⁶)
:::

::: ex
A = **10 MIPS** @ 33 MHz และ B = **9 MIPS** @ 20 MHz โปรแกรมเดียวกันใช้ 12M คำสั่งบน A และ 10M คำสั่งบน B (เพราะ ISA ต่างกัน)
- T<sub>A</sub> = 12M / 10M = **1.2 s** และ T<sub>B</sub> = 10M / 9M = **1.11 s**
- → **B เร็วกว่าทั้งที่ MIPS ต่ำกว่า**
:::

::: trap
**MIPS ใช้เทียบข้าม ISA ไม่ได้** เพราะ "1 คำสั่ง" ของแต่ละ ISA ทำงานได้ไม่เท่ากัน (IC ต่างกัน) และ **clock สูงกว่าก็ไม่ได้แปลว่าเร็วกว่า**
:::

## 2.6 Amdahl's Law

::: term
[Amdahl's Law]{.abbr} [กฎของแอมดาห์ล ("Law of diminishing returns")]{.th}

- **คืออะไร:** สูตรหา **overall speedup** เมื่อเร่งได้**เพียงบางส่วน**ของงาน (โดย Gene M. Amdahl, 1922–2015)
- **สูตร:** **Speedup = 1 / ((1 − P) + P/n)**
  - P = **สัดส่วนของเวลาเดิม**ที่ถูกเร่ง
  - n = speedup ของส่วนนั้น
- **ขีดจำกัด:** เมื่อ n → ∞ ได้ **S<sub>max</sub> = 1 / (1 − P)** → **ส่วนที่ไม่ได้เร่งเป็นตัวจำกัด**
- **หลักที่ได้:** **"Make the common case fast"** (เร่งส่วนที่กินเวลามากที่สุดก่อน)
- **สัมพันธ์กับ:** multicore/parallelism (Ch7) เพราะส่วน serial จำกัด speedup
:::

::: ex
**ซื้อของ:** มี 2 ส่วนคือ เดินทาง (A) ซึ่งกินเวลามากกว่า กับ เลือกซื้อ (B)
- **ทำ A เร็วขึ้น 2 เท่าได้ผลดีกว่าทำ B เร็วขึ้น 5 เท่า** เพราะ A กินเวลามากกว่า

**ซื้ออาหาร:** การซื้อกินเวลา 1/3 ของมื้อ ทำให้เร็วขึ้น 3 เท่า
- 1 / (2/3 + 1/9) = 9/7 ≈ **1.29**
:::

::: ex
**Exercises ท้ายบท**
1. Mail server: computation 40% เร็วขึ้น 10 เท่า (I/O 60%) → 1 / (0.6 + 0.04) = **1.5625**
2. FP เร็วขึ้น 1.6 เท่า และ FP กินเวลาครึ่งหนึ่ง → 1 / (0.5 + 0.5/1.6) = **1.23**
3. FP 25% (CPI 4.0), อื่น ๆ CPI 1.33 และลด CPI ของ FP เหลือ 2.5
   - CPI<sub>เดิม</sub> = 0.25(4) + 0.75(1.33) ≈ **2.0**
   - CPI<sub>ใหม่</sub> = 0.25(2.5) + 0.9975 = **1.6225**
   - Speedup = 2.0 / 1.6225 ≈ **1.23**
:::

::: trap
**P ใน Amdahl ต้องเป็นสัดส่วนของ "เวลา"** ไม่ใช่ "จำนวนคำสั่ง"
- ข้อ 3 FP มี 25% ของคำสั่ง แต่กินเวลา 1.0 / 2.0 = **50%**
- ถ้าแทน P = 0.5 และ n = 4/2.5 = 1.6 จะได้ 1.23 เท่ากัน
- ถ้าแทน P = 0.25 คำตอบจะผิด
:::
