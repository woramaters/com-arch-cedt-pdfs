# Ch3: Instruction Set Architecture

## 3.1 ภาพรวม

ISA คือทุกสิ่งที่ต้องรู้เพื่อเขียน assembly หรือสร้าง system software (OS, compiler, assembler) ได้แก่ **(1) instructions/operators** (RTL, CPI, format) **(2) operands, registers, flags** **(3) memory reference** (addressing, referencing, dereferencing) **(4) instruction format** (การ encode เป็น binary) และ **(5) interrupt & exception handler**

**ประวัติของวิชา:**

| ยุค | เน้นเรื่อง |
|---|---|
| 50s–60s | computer arithmetic |
| 70s–80s | ISA design และ ISA for compiler (Pascal, Ada, stack frame) |
| 90s | CPU organization, memory, ISA extension (multimedia, Nvidia/ATI) |
| 2000s | parallelism, multi-core, 64-bit, PCIe, USB |
| 2010s | GPU/deep learning, virtualization, distributed |

::: term
[IBM System/360]{.abbr} [IBM 360 (ปี 1964)]{.th}

- **คืออะไร:** สถาปัตยกรรมที่ IBM เปิดตัวในปี 1964 โดย**รวม instruction set ที่ไม่เข้ากัน 7 แบบให้เป็นแบบเดียว**
- **ความสำคัญ:** ก่อนหน้านั้นโปรแกรม**ไม่ portable** (ย้ายเครื่องแล้วต้องเขียนใหม่) และ IBM 360 เป็นจุดเริ่มของแนวคิด "ISA เดียว หลาย implementation"
:::

### ส่วนประกอบของภาษา Assembly

```
main:  ORI  $r1, $r0, #10    ; label: OPCODE dest, src, #immediate
       ORI  $r2, $r0, #20    ; $r0 = 0 เสมอ ดังนั้น $r2 = 20
       ADD  $r3, $r1, $r2    ; $r3 = $r1 + $r2
       SD   $r3, [100]       ; [100] = memory ที่ address 100  (C = 10 + 20)
```

::: term
[Opcode]{.abbr} [Operation code]{.full} [รหัสคำสั่ง]{.th}

- **คืออะไร:** ส่วนของคำสั่ง (binary) ที่บอกว่าเป็น**คำสั่งอะไร** เช่น ADD หรือ LW
- **สัมพันธ์กับ:** control unit **decode** opcode เพื่อสร้าง control signals ส่วน nanoLADA ใช้ opcode 6 bits
:::

::: term
[Operand / Immediate]{.abbr} [ตัวถูกดำเนินการ / ค่าคงที่ในคำสั่ง]{.th}

- **Operand:** ข้อมูลที่คำสั่งใช้ อยู่ได้ใน register, memory หรือในตัวคำสั่งเอง
- **Immediate:** operand ที่**ฝังอยู่ในตัวคำสั่ง** (เขียนว่า `#10`) ไม่ต้องไปอ่านจากที่อื่น
:::

::: term
[Label]{.abbr} [ป้ายชื่อตำแหน่ง]{.th}

- **คืออะไร:** ชื่อแทน address ของคำสั่ง (เช่น `main:` หรือ `Loop:`) ที่ assembler แปลงเป็นตัวเลขหรือ displacement ให้
:::

::: term
[Flag / Status register]{.abbr} [บิตสถานะ]{.th}

- **คืออะไร:** บิตที่บอกผลของคำสั่งล่าสุด เช่น **Zero**, Carry, Overflow, Negative
- **สัมพันธ์กับ:** ใช้ตัดสิน branch และ **ต้องถูก save ตอนเกิด exception/subroutine** ("save status")
:::

## 3.2 Design Issues และคุณสมบัติของ ISA ที่ดี

**Design issues 3 ข้อ:**
1. operand เก็บที่ไหน (accumulator, stack, registers, memory)
2. มี explicit operand กี่ตัว (0, 1, 2, 3)
3. ระบุ operand อย่างไร (addressing mode: immediate, direct, indirect, displacement)

**ISA Matrix (คุณสมบัติที่ต้องการ):**

| คุณสมบัติ | ความหมาย |
|---|---|
| **Compatibility** | software portable รันได้ข้ามรุ่น |
| **Generality / Completeness** | รองรับ operation ได้หลากหลาย |
| **Orthogonality** | มี special case น้อย ใช้**ทุก addressing mode กับทุก data type/instruction ได้** |
| **Regularity** | ไม่ overload ความหมายของ field ในคำสั่ง |
| **Ease of compilation** | compiler สร้างโค้ดได้ง่าย |
| **Ease of implementation** | hardware สร้างได้ง่าย |

## 3.3 ISA 5 แบบ (ตามตำแหน่งของ operand)

ทุกตัวอย่างคำนวณ **x = (a·b) + (a − (b·c))** และในอดีตนิยมแบบที่ใช้ memory เยอะ เพราะ**ตอนนั้น DRAM เร็วเมื่อเทียบกับ CPU และ transistor แพง**

::: term
[Accumulator architecture]{.abbr} [สถาปัตยกรรมแบบตัวสะสม (ก่อน 1960)]{.th}

- **คืออะไร:** มี register หลักตัวเดียวคือ **accumulator (ACC)** ซึ่งเป็น**ทั้ง source และ destination โดยปริยาย (implicit)** ทำให้คำสั่งระบุ address เพียง 1 ตัว (**1-address**)
- **ตัวอย่าง:** `LD A,[a]; MUL A,[b]; SD A,[x]; ...` ใช้ **11 คำสั่ง**
- **Pros:** hardware น้อยมาก ออกแบบและเข้าใจง่าย
- **Cons:** ACC เป็น **bottleneck**, ไม่เหมาะกับ parallelism/pipeline, **memory traffic สูง** (ต้องเก็บค่ากลางลง memory)
:::

::: term
[Stack architecture]{.abbr} [สถาปัตยกรรมแบบสแตก (1960s–70s)]{.th}

- **คืออะไร:** operand อยู่ที่ **top of stack** โดยปริยาย คำสั่งคำนวณจึงไม่ต้องระบุ operand (**0-address**)
- **ตัวอย่าง:** `PUSH a; PUSH b; MUL; PUSH a; PUSH b; PUSH c; MUL; SUB; ADD; POP x` ใช้ **10 คำสั่ง**
- **Pros:** hardware น้อย, **code density ดี** (คำสั่งสั้น), compiler สร้างโค้ดง่าย
- **Cons:** stack เป็น bottleneck, **ข้อมูลที่ต้องการไม่ได้อยู่ top of stack เสมอ**, optimize ยาก, ไม่เหมาะกับ pipeline
- **สัมพันธ์กับ:** Java bytecode / JVM เป็น stack machine
:::

::: term
[Memory-Memory architecture]{.abbr} [สถาปัตยกรรมแบบหน่วยความจำ-หน่วยความจำ (1970s–80s)]{.th}

- **คืออะไร:** คำนวณกับ operand ใน memory โดยตรง (**2–3 address**)
- **ตัวอย่าง:** แบบ 3-operand `MUL k,a,b; MUL i,b,c; SUB j,a,i; ADD x,k,j` ใช้ **4 คำสั่ง** ส่วนแบบ 2-operand ใช้ **7 คำสั่ง**
- **Pros:** **จำนวนคำสั่งน้อยที่สุด**, compiler ง่าย
- **Cons:** **memory traffic สูงมาก**, **CPI แปรผัน** (ขึ้นกับจำนวนการเข้าถึง memory) และแบบ 2-operand ต้องย้ายข้อมูลเพิ่ม
- **ตัวอย่างเครื่องจริง:** VAX
:::

::: term
[Register-Memory architecture]{.abbr} [สถาปัตยกรรมแบบรีจิสเตอร์-หน่วยความจำ (1970s–ปัจจุบัน)]{.th}

- **คืออะไร:** คล้าย accumulator แต่มี**หลาย register** โดย operand หนึ่งตัวอยู่ใน memory ได้ (**2-address**)
- **ตัวอย่าง:** `LD r1,a; MUL r1,b; ...` ใช้ **10 คำสั่ง**
- **Pros:** ใช้ข้อมูลใน memory ได้เลยโดยไม่ต้อง load ก่อน, encode ง่าย, code density ดี
- **Cons:** **poor orthogonality** (operand สองตัวมีสิทธิ์ไม่เท่ากัน), CPI แปรผัน, อาจจำกัดจำนวน register
- **ตัวอย่างเครื่องจริง:** **x86**
:::

::: term
[Register-Register / Load-Store architecture]{.abbr} [สถาปัตยกรรมแบบรีจิสเตอร์-รีจิสเตอร์ (1960s–ปัจจุบัน)]{.th}

- **คืออะไร:** operand ของคำสั่งคำนวณเป็น **register เท่านั้น** (**3-address**) และ **เข้าถึง memory ได้ผ่าน LOAD/STORE เท่านั้น**
- **ตัวอย่าง:** `LD r1,a; LD r2,b; LD r3,c; MUL r4,r1,r2; MUL r5,r2,r3; SUB r6,r1,r5; ADD r7,r4,r6; SD r7,x` ใช้ **8 คำสั่ง**
- **Pros:** **fixed-length encode ง่าย**, **CPI ใกล้เคียงกันทุกคำสั่ง**, **pipeline/parallelism ง่าย**
- **Cons:** IC สูงกว่า, performance ขึ้นกับ compiler ที่ดี
- **ตัวอย่างเครื่องจริง:** MIPS, ARM, RISC-V, **nanoLADA**
:::

| แบบ | #address | #คำสั่ง | จุดเด่น | จุดด้อย |
|---|---|---|---|---|
| Accumulator | 1 | 11 | HW น้อยที่สุด | bottleneck, memory traffic สูง |
| Stack | 0 | 10 | code density ดี | data ไม่อยู่ top เสมอ |
| Mem-Mem | 2–3 | 4 / 7 | คำสั่งน้อยที่สุด | memory traffic สูงที่สุด |
| Reg-Mem | 2 | 10 | ไม่ต้อง load ก่อน | ไม่ orthogonal |
| **Load-Store** | 3 | 8 | **ดีที่สุดสำหรับ pipeline** | IC สูง |

::: term
[CISC / RISC]{.abbr} [Complex / Reduced Instruction Set Computer]{.full}

- **CISC:** คำสั่ง**ทรงพลังและซับซ้อน** (1 คำสั่งทำงานได้มาก) มีความยาวแปรผันและ addressing mode เยอะ เช่น x86, VAX → IC ต่ำ แต่ CPI สูงและ control ซับซ้อน
- **RISC:** คำสั่งเป็น **building block พื้นฐาน** แบบ fixed-length load-store เช่น MIPS, ARM → IC สูง แต่ CPI ต่ำและ T<sub>c</sub> สั้น
- **ใครชนะ:** **เมื่อมี ILP (pipeline) เข้ามา RISC ชนะ**
- **ยุค Post-RISC:** Intel (CISC) **แปลคำสั่งเป็น RISC ภายใน (micro-ops)** ก่อนทำ parallelism → เส้นแบ่งไม่ชัดแล้ว
- **ARM = Acorn RISC Machine** ซึ่งเด่นเรื่อง**ประหยัดพลังงาน** (อุปกรณ์ mobile)
:::

## 3.4 Memory Organization

Memory คือ **array ขนาดใหญ่ที่ index ด้วย address** และใช้ **byte addressing** (1 address = 1 byte) ถ้าต้องการบิตเดียวให้ใช้ **bit mask** (AND/OR) ขนาดใน C: char 1, short 2, int 4, long 8, float 4, double 8, long double 16 bytes ข้อมูลหลาย byte ทำให้เกิดคำถาม 2 ข้อ คือ **ordering (endian)** และ **parallelism (alignment)**

::: term
[Endianness]{.abbr} [ลำดับการเก็บไบต์]{.th}

- **คืออะไร:** ข้อตกลงว่าข้อมูลหลาย byte จะเก็บ byte ไหนไว้ที่ address ต่ำ โดยอ้างถึงตัวแปรด้วย **base address = address ต่ำสุด**
- **Little endian:** **byte ต่ำ (LSB) อยู่ address ต่ำ** ใช้โดย **Intel**
- **Big endian:** **byte สูง (MSB) อยู่ address ต่ำ** ใช้โดย **IBM PowerPC, Sun** และไฟล์ **Photoshop** (เก็บแบบ big endian เสมอ)
- **Bi-endian:** **ARM (ตั้งแต่ ARM6)** เลือกได้ทั้งสองแบบ
- **ทำไมสำคัญ:** การส่งไฟล์ binary ระหว่าง Mac PowerPC (big) กับ Windows PC (little) ต้องแปลงลำดับ byte
:::

| เก็บ 0x1A2B3C4D | addr 00 | 01 | 02 | 03 |
|---|---|---|---|---|
| **Big endian** | 1A | 2B | 3C | 4D |
| **Little endian** | 4D | 3C | 2B | 1A |

::: key
**Endian กับ performance** (เมื่อ bus เล็กกว่าข้อมูล ระบบจะอ่านจาก address ต่ำไปสูง)
- **บวกเลข → little endian ดีกว่า** เพราะได้ byte ต่ำก่อน จึงบวกและส่ง carry ต่อได้ทันที
- **เปรียบเทียบมาก/น้อย → big endian ดีกว่า** เพราะได้ byte สูง (มี sign bit) ก่อน จึงตอบได้ทันที
:::

::: term
[Alignment]{.abbr} [การจัดแนวข้อมูล]{.th}

- **คืออะไร:** ข้อกำหนดว่าข้อมูลขนาด s bytes ต้องเริ่มที่ address แบบไหน
- **ทำไมต้องมี:** memory อ่านได้ทีละหลาย byte พร้อมกัน (parallelism) ถ้าข้อมูลคร่อมขอบ ต้องอ่าน 2 ครั้ง
- **Restricted alignment:** ต้องมี **Base Address mod size = 0**
  - **ภาระอยู่ที่ software/compiler** (ต้องใส่ padding)
  - HW ตรวจเจอ misalignment แล้ว **trap**
  - **ไม่เสียเวลาเพิ่ม** → **ชนะในแง่ performance** ("make the common case fast")
- **Unrestricted alignment:** วางที่ไหนก็ได้
  - software ง่าย แต่ **HW ต้องตรวจและแก้เอง** มักต้องเข้าถึง memory **2 ครั้งขึ้นไป** (ช้า, logic แพง)
  - บางครั้งต้องมีเพื่อ backward compatibility
- **สัมพันธ์กับ:** **ABI** กำหนด alignment และ padding ใน struct
:::

::: ex
Restricted alignment ของ `char a; short b; int c; char d; long e; double f;`

| Addr | 0 | 1 | 2–3 | 4–7 | 8 | 9–15 | 16–23 | 24–31 |
|---|---|---|---|---|---|---|---|---|
| | a | pad | b | c | d | pad 7 B | e | f |

- รวม **32 bytes**
- ถ้าเรียงตัวแปรใหม่จากใหญ่ไปเล็กจะเหลือ 8 + 8 + 4 + 2 + 1 + 1 = 24 bytes
:::

::: term
[Padding]{.abbr} [ไบต์เติมช่องว่าง]{.th}

- **คืออะไร:** byte ว่างที่ compiler ใส่เพื่อให้ตัวแปรถัดไป aligned
- **วิธีหาตำแหน่ง:** ตำแหน่งถัดไปต้องเป็น**พหุคูณของขนาดตัวแปร** (int → หาร 4 ลงตัว, double → หาร 8 ลงตัว)
:::

## 3.5 Addressing Modes

::: term
[Addressing mode]{.abbr} [วิธีระบุตำแหน่งของ operand]{.th}

- **คืออะไร:** กฎที่บอกว่าจะหาค่า operand หรือ **EA (Effective Address)** ได้อย่างไร
- **ทำหน้าที่:** ทำให้โปรแกรมอ้างถึงข้อมูลแบบต่าง ๆ (ตัวแปร, array, pointer, struct) ได้สะดวก
:::

| # | Mode | ตัวอย่าง | วิธีหาค่า | ตรงกับ C |
|---|---|---|---|---|
| 1 | **Immediate** | `LDI r1, #4` | ค่าอยู่ในคำสั่ง | A = 4 |
| 2 | **Register (direct)** | `ADD r1,r2,r3` | ค่าอยู่ใน register | A = B + C |
| 3 | **Displacement** | `LD r1, 100(r2)` | M[R2 + 100] | **A = G.age** (field ของ struct) หรือ local variable |
| 4 | **Register Indirect** | `LD r1, (r2)` | M[R2] | **A = \*p** |
| 5 | **Index** | `LD r1, (r2+r3)` | M[R2 + R3] | **A = D[i]** |
| 6 | **Direct / Absolute** | `LD r1, 1000` | M[1000] | ตัวแปร global |
| 7 | **Memory Indirect** | `LD r1, @(r2)` | M[M[R2]] | **A = \*\*p** |
| 8 | **Auto-increment** | `LD r1, (r2)+` | M[R2] แล้ว R2 += size | **A = D[i++]** |
| 9 | **Auto-decrement** | `LD r1, (r2)-` | M[R2] แล้ว R2 −= size | **A = D[i−−]** |
| 10 | **Scale** | `LD r1, (r2)[r3*4]` | M[R2 + R3 × 4] | **F = E[i]** (int 4 bytes) |

::: key
- **Register indirect แทน mode อื่นได้เกือบทั้งหมด** (คำนวณ address ใส่ register ก่อนแล้วค่อยใช้)
- **Trend ของ ISA ใหม่:** รองรับเฉพาะ **displacement, immediate และ register indirect** โดย **displacement field 12–16 bits** และ **immediate field 8–16 bits** ส่วน mode ซับซ้อนให้ **compiler แปลงเป็น mode ง่าย** และให้ HW โฟกัสที่ mode ง่าย
:::

## 3.6 ประเภทคำสั่งและ Control Flow

| ประเภท | หน้าที่ | ตัวอย่าง |
|---|---|---|
| **Data movement/transfer** | ย้ายข้อมูลระหว่าง memory, register, I/O | LW, SW |
| **Arithmetic** | คำนวณเลข | ADD, SUB, MUL, DIV |
| **Logic** | operation ทางตรรกะ | AND, OR, XOR, NOT (Com) |
| **Control** | เปลี่ยน PC (ปกติ PC ← PC + 4) | JMP, BEQ, CALL, RET |
| **Extended** | คำสั่งเฉพาะทาง | multimedia (SIMD), encryption |

::: term
[PC]{.abbr} [Program Counter]{.full} [ตัวนับโปรแกรม]{.th}

- **คืออะไร:** register พิเศษที่เก็บ **address ของคำสั่งถัดไป**
- **ทำงานอย่างไร:** ปกติ PC ← PC + 4 (คำสั่งยาว 4 bytes) ส่วนคำสั่ง control flow จะเขียนค่าใหม่ลง PC
- **สัมพันธ์กับ:** **Fetch** อ่าน MEM[PC], branch, exception (save PC) และ pipeline ที่แต่ละ stage มี PC ของคำสั่งต่างกัน
:::

::: term
[Branch vs Jump]{.abbr} [กระโดดแบบมีเงื่อนไข vs ไม่มีเงื่อนไข]{.th}

- **Branch:** กระโดด**เมื่อเงื่อนไขเป็นจริง** (เช่น BEQ) มักใช้ **PC-relative displacement**
- **Jump:** กระโดด**เสมอ** (เช่น JMP) ไปยัง address ที่ระบุ
- **สัมพันธ์กับ:** เป็นต้นเหตุของ **control hazard** ใน pipeline (Ch6)
:::

::: term
[PC-relative addressing]{.abbr} [การอ้างตำแหน่งเทียบกับ PC]{.th}

- **คืออะไร:** ปลายทางของการกระโดด = PC + displacement
- **ทำไมนิยม:**
  - ทำให้โปรแกรม **relocatable** (ย้ายไปวางที่ address ไหนก็ทำงานได้)
  - branch ส่วนใหญ่กระโดดใกล้ ๆ จึงใช้ field เล็กได้
- **กรณีที่ใช้ไม่ได้:** address ที่**ไม่รู้ตอน compile** เช่น **shared library / dynamic binding** ต้องใช้ **register ที่เก็บ address** (`CALL $r14`) และ symbol table
:::

### Subroutine

::: term
[Subroutine / Procedure call]{.abbr} [การเรียกโปรแกรมย่อย]{.th}

- **ขาเรียก:**
  1. ส่ง parameter
  2. save status
  3. **save return address**
  4. เปลี่ยน PC ไปที่ subroutine
  5. ทำงาน
  6. save return data
- **ขากลับ:** restore status แล้ว **load return address กลับเข้า PC**
- **ใครกำหนดรายละเอียด:** **ABI**
:::

::: term
[Parameter passing]{.abbr} [การส่งพารามิเตอร์]{.th}

- **ผ่าน register:** เร็ว เช่น `LI $r3,#5; LI $r4,#4; CALL _min`
- **ผ่าน stack frame:** `PUSH #5; PUSH #4; CALL _min` แล้ว callee อ่านด้วย `LD $r3,[$r14+4]` (`$r14` = stack pointer)
- **Stack frame:** พื้นที่บน stack ของการเรียกแต่ละครั้ง (parameter, return address, local variable)
:::

::: term
[Caller-save vs Callee-save]{.abbr} [ผู้เรียกเก็บ vs ผู้ถูกเรียกเก็บ]{.th}

- **Caller-save:** **ผู้เรียก** PUSH register ที่ตัวเองใช้ก่อน CALL แล้ว POP คืนหลังกลับมา
  - ปัญหา: caller **ไม่รู้ว่า callee ใช้ register ไหน** จึงอาจ save เกินจำเป็น
- **Callee-save:** **subroutine** PUSH เฉพาะ register ที่**ตัวเองจะแก้** แล้ว POP ก่อน RET → **มักคุ้มกว่า** (save เท่าที่ใช้จริง)
- **x86** มี `PUSHA/POPA` ที่ save ทุก register (**ง่ายแต่ช้า**)
:::

## 3.7 Exceptions และ Interrupts

::: term
[Exception]{.abbr} [ข้อยกเว้น / เหตุการณ์ที่ทำให้ control flow เปลี่ยนโดยไม่ได้เขียนไว้]{.th}

- **คืออะไร:** **"Unprogrammed control flow"** คือการเปลี่ยน PC ที่โปรแกรมไม่ได้สั่งตรง ๆ
- **แบ่งตามแหล่ง:**
  - **Interrupt:** มาจาก **hardware ภายนอก** (เช่น keyboard, timer, disk เสร็จงาน)
  - **Trap:** มาจาก **software** (เช่น system call, หารด้วยศูนย์, misalignment, page fault)
  - Intel เรียกทั้งสองแบบว่า interrupt
- **ขั้นตอน (คล้าย subroutine):**
  1. save status
  2. **save PC**
  3. เรียก **handler**
  4. ทำงาน
  5. restore status
  6. restore PC (เช่นคำสั่ง IRET)
:::

::: term
[ISR / Handler]{.abbr} [Interrupt Service Routine]{.full} [โปรแกรมจัดการ interrupt]{.th}

- **คืออะไร:** โค้ดที่รันเมื่อเกิด exception หรือ interrupt แหล่งนั้น ๆ
- **ปัญหา:** CPU ต้องรู้ว่า handler อยู่ที่ไหน ซึ่งมี 3 วิธีตามตารางด้านล่าง
:::

| วิธี | ตารางเก็บอะไร | หา handler อย่างไร | ตัวอย่าง (base 0x8000, interrupt 8) |
|---|---|---|---|
| **Vector Table** | **address** ของ handler | addr = **mem[Base + n × address size]** แล้วกระโดดไปที่ค่านั้น (อ่าน memory 1 ครั้ง) | 32-bit address: mem[0x8000 + 8 × 4] = **mem[0x8020]** |
| **Handler Table** | **ตัวโค้ด** ของ handler (ขนาดคงที่) | addr = **Base + n × handler size** กระโดดไปได้ทันที | handler 16 B: 0x8000 + 8 × 16 = **0x8080** |
| **Fixed Entry** | ไม่มีตาราง | CPU กระโดดไป **0x1000 เสมอ** แล้ว **software อ่าน interrupt-source register** เพื่อตัดสินใจเอง | — |

## 3.8 Instruction Format

::: term
[Instruction format / Encoding]{.abbr} [รูปแบบการเข้ารหัสคำสั่ง]{.th}

- **คืออะไร:** การจัด field (opcode, register, immediate) ลงใน binary ของคำสั่ง
- **มีผลต่อ:** **ขนาดของ code** และ **งาน decode ของ processor**
- **ขึ้นกับ:** จำนวน addressing mode และความเป็นอิสระระหว่าง opcode กับ mode
- **สิ่งที่ต้องการ (ขัดแย้งกัน):** register และ addressing mode เยอะ, คำสั่งสั้น (code เล็ก), decode/implement ง่าย
:::

| แบบ | ลักษณะ | ข้อดี | ข้อเสีย | ตัวอย่าง |
|---|---|---|---|---|
| **Variable length** | บิตแรกบอกความยาว ใช้ address specifier | รองรับ mode เยอะ **code เล็ก** | decode ยาก | x86, VAX |
| **Fixed length** | mode น้อย opcode บอก mode | **decode ง่าย ทำ pipeline ง่าย** | code ใหญ่กว่า | nanoLADA, MIPS |
| **Hybrid** | ผสมกัน | | | ARM Thumb (และรัน Java bytecode บนชิปได้ที่ CPI สูงขึ้น) |

::: ex
**ถ้าต้องการ performance แบบ fixed length ชนะ**

ตัวอย่างในสไลด์: **code ของ MIPS ใหญ่ประมาณ 2 เท่าของ VAX แต่ CPI เป็น 1/6** (สมมติ clock เท่ากัน)
- T<sub>MIPS</sub> / T<sub>VAX</sub> = (2 × IC) × (CPI/6) / (IC × CPI) = 2/6 = 1/3
- → **MIPS เร็วกว่าประมาณ 3 เท่า**
:::

## 3.9 Compiler และ Optimization

::: term
[Compiler]{.abbr} [ตัวแปลภาษา]{.th}

- **คืออะไร:** โปรแกรมแปลภาษาระดับสูงเป็น machine code โดย **ISA เป็นเป้าหมาย (target) ของ compiler**
- **Goals:** **correctness** (สำคัญที่สุด), speed ของโค้ด, compile time และ debugging support
- **ขั้นตอน:**
  1. front-end (ภาษา → **intermediate code**)
  2. high-level optimization
  3. global optimization
  4. **code generator** (machine-dependent)
:::

::: term
[Basic block]{.abbr} [บล็อกพื้นฐาน]{.th}

- **คืออะไร:** ลำดับคำสั่งที่**ไม่มี jump/branch เข้าหรือออกตรงกลาง** (เข้าที่หัว ออกที่ท้าย)
- **สัมพันธ์กับ:** local optimization ทำภายใน basic block และใน Ch7 **basic block ใหญ่ = มีโอกาสหา ILP มาก** (loop unrolling ทำให้ใหญ่ขึ้น)
:::

| ระดับ | Optimization | ความหมาย |
|---|---|---|
| High-level | **Procedure integration (inlining)** | แทนการเรียกฟังก์ชันด้วยตัวโค้ดของฟังก์ชัน (ประหยัด call/return) |
| Local | **Common subexpression elimination (CSE)** | นิพจน์ที่คำนวณซ้ำให้คำนวณครั้งเดียว |
| Local | **Constant propagation** | แทนตัวแปรที่รู้ค่าคงที่ด้วยค่านั้น |
| Local | Stack height reduction | จัดลำดับการคำนวณให้ใช้ stack น้อยลง |
| Global | Global CSE | CSE ข้าม basic block |
| Global | **Copy propagation** | แทน `y` ด้วย `x` หลังจาก `y = x` |
| Global | **Code motion** | **ย้ายโค้ดที่ไม่เปลี่ยนค่าใน loop (loop-invariant) ออกนอก loop** |
| Machine-dependent | **Strength reduction** | ใช้ operation ที่ถูกกว่าแทน เช่น **shift แทนการคูณ** (x × 8 → x << 3) |
| Machine-dependent | Branch offset optimization | เลือกขนาด displacement ให้เหมาะ |
| Machine-dependent | **Pipeline scheduling** | จัดลำดับคำสั่งเพื่อลด stall (Ch6) |

::: ex
- **Copy/constant propagation:** `m=60; h=60*m; d=24*h; days=seconds/d;` → `days = seconds/86400;`
- **CSE:** `a=b+c+d; y=b+c+e;` → `x=b+c; a=x+d; y=x+e;`
- **Code motion:** loop `for(x=0;x<=100;x++){ hs=3600; ds=hs*24; h=a[x]/hs; d=a[x]/ds; }` → ย้าย `hs=3600; ds=86400;` (พร้อมทำ constant folding) **ออกนอก loop**
- **Copy propagation ของ `A=B+C; B=A+C; D=A-B;`**
  - → `B = B+C+C` ซึ่ง**งานเพิ่มขึ้น** (บวก 2 ครั้ง)
  - → `D = (B+C)−(B+C+C) = −C` ซึ่ง**งานลดลงมาก**
  - → optimization **ไม่ได้ลดงานเสมอ** compiler ต้องชั่งน้ำหนัก
:::

::: key
**ข้อสังเกตเรื่อง optimization (Effectiveness):**
- โปรแกรม "**locally simple, globally complex**"
- **bug ส่วนใหญ่ของ compiler มาจาก optimization**
- **Alias (pointer) ทำให้เก็บตัวแปรไว้ใน register ไม่ได้** เพราะ compiler ไม่รู้ว่า pointer จะแก้ตัวแปรไหน

**ISA แบบไหนช่วย compiler writer:**
- **Regularity** (orthogonality ระหว่าง addressing mode, data type, operation)
- **Simplicity** ("**provide primitives, not solutions**")
- ทำให้ trade-off ชัดเจน
- allow compile-time binding
- **Make the common case fast**
:::

::: ex
**Clear register แบบไหนเร็วที่สุด** (`CLR R1`, `MOV R1,0`, `SUB R1,R1,R1`, `XOR R1,R1,R1`)
- สไลด์บอกว่า **XOR แนะนำสำหรับ architecture ส่วนใหญ่**
- เหตุผล: ไม่ต้องมี immediate (คำสั่งสั้น) และ HW รู้จัก idiom นี้ (เป็น hardware-specific optimization)
:::
