# Ch8: Memory Organization

## 8.1 ภาพรวม: ทำไมต้องมี Memory Hierarchy

- ยุค 70s memory **เร็วกว่า** CPU (และ 640 KB ก็พอใช้) แต่ปัจจุบัน memory **ช้ามากเมื่อเทียบกับ** CPU และต้องการอย่างน้อย 4–8 GB
- ปี 1980 CPU ยังไม่มี cache ส่วนปี 1995 มี cache 2 ระดับแล้ว

::: ex
memory op ใช้ 50 cycles, op อื่นใช้ 1 cycle และมี memory op 10%
- สัดส่วนเวลาที่ CPU รอ memory = (0.1 × 50) / (0.9 × 1 + 0.1 × 50) = 5 / 5.9 ≈ **85%**
:::

**Design goal:** อยากได้ memory ที่ **large, fast และ cheap** ซึ่งทำได้ด้วย **hierarchy + parallelism** (กฎทางกายภาพคือ large memory is slow)

::: term
[Memory hierarchy]{.abbr} [ลำดับชั้นของหน่วยความจำ]{.th}

- **คืออะไร:** จัด memory เป็นหลายระดับ โดย**ระดับที่ใกล้ CPU จะเล็ก เร็ว และแพงต่อ bit** ส่วนระดับไกลจะใหญ่ ช้า และถูก
- **ลำดับ:** Registers → Cache (L1, L2, ...) → Main memory (DRAM) → Disk/SSD
- **ทำไมได้ผล:** อาศัย **locality** ทำให้ข้อมูลส่วนใหญ่ที่ใช้อยู่ในระดับเร็ว → **รู้สึกเหมือนมี memory ใหญ่เท่าระดับล่างแต่เร็วเท่าระดับบน**
- **หมายเหตุ:** สไลด์เรียกระดับที่ใกล้ processor ว่า "lower level"
:::

| ระหว่าง | ใครจัดการ |
|---|---|
| Registers ↔ Memory | **Software** (compiler หรือ programmer) |
| Cache ↔ Memory | **Hardware** (transparent ต่อ software) |
| Memory ↔ Disk | **Hardware + OS** (virtual memory/paging) หรือ programmer (ผ่านไฟล์) |

## 8.2 Memory Technology

::: term
[RAM]{.abbr} [Random Access Memory]{.full} [หน่วยความจำเข้าถึงแบบสุ่ม]{.th}

- **คืออะไร:** memory ที่ **"random" = เวลาเข้าถึงคงที่ทุกตำแหน่ง** (ไม่ได้แปลว่าสุ่ม)
- **ตรงข้ามกับ:**
  - **Semi-random:** disk, CD/DVD (ต้อง seek + rotate)
  - **Sequential access:** **tape** (เวลาแปรตามตำแหน่งแบบ linear)
:::

::: term
[DRAM]{.abbr} [Dynamic RAM]{.full} [แรมแบบไดนามิก]{.th}

- **ทำจาก:** **capacitor** (1 transistor + 1 capacitor ต่อบิต)
- **คุณสมบัติ:** **high density, low power, cheap, slow** และ**ต้อง refresh เป็นระยะ** (ประจุรั่ว จึงเรียกว่า dynamic)
- **ใช้เป็น:** **main memory**
:::

::: term
[SRAM]{.abbr} [Static RAM]{.full} [แรมแบบสถิต]{.th}

- **ทำจาก:** **transistor** (flip-flop ประมาณ 6 ตัวต่อบิต)
- **คุณสมบัติ:** **low density, high power, expensive, fast** และ**ค่าอยู่ตลอดตราบที่มีไฟ** (ไม่ต้อง refresh)
- **ใช้เป็น:** **cache**
:::

## 8.3 Principle of Locality

::: term
[Locality]{.abbr} [หลักความใกล้เคียงของการเข้าถึง]{.th}

- **คืออะไร:** **ณ เวลาหนึ่ง โปรแกรมเข้าถึง address เพียงก้อนเล็ก ๆ** ถ้าเอาก้อนนี้ไว้ในระดับเร็ว ระบบจะรู้สึกว่าเร็วทั้งหมด
- **มี 2 แบบ:** temporal และ spatial
:::

::: term
[Temporal locality]{.abbr} [ความใกล้เคียงเชิงเวลา ("tempo" = เวลา)]{.th}

- **คืออะไร:** **ข้อมูลที่เพิ่งใช้มีแนวโน้มถูกใช้อีกเร็ว ๆ นี้**
- **ตัวอย่าง:** ตัวแปรใน loop, เบอร์ที่เพิ่งโทรควรอยู่บนสุดของ recent list
- **Cache ใช้ประโยชน์โดย:** เก็บข้อมูลที่เพิ่งใช้ไว้ และใช้ LRU replacement
:::

::: term
[Spatial locality]{.abbr} [ความใกล้เคียงเชิงพื้นที่]{.th}

- **คืออะไร:** **ข้อมูลที่อยู่ใกล้กับข้อมูลที่เพิ่งใช้มีแนวโน้มถูกใช้ตามมา**
- **ตัวอย่าง:** array ที่อ่านเรียงกัน, คำสั่งที่รันต่อกัน, ดึงเบอร์ของเพื่อนของเพื่อนมาพร้อมกัน, พกดินสอกับยางลบคู่กัน
- **Cache ใช้ประโยชน์โดย:** ดึงข้อมูลมาทีละ **block** (block ใหญ่ = spatial ดีขึ้น)
:::

## 8.4 Cache: คำศัพท์พื้นฐาน

::: term
[Cache]{.abbr} [หน่วยความจำแคช]{.th}

- **คืออะไร:** หน่วยความจำ SRAM ขนาดเล็กและเร็ว อยู่ระหว่าง CPU กับ main memory โดย**เก็บสำเนาของข้อมูลที่เพิ่งใช้หรือน่าจะได้ใช้**
- **การจัดการ:** **hardware** ทั้งหมด (transparent ต่อ software)
- **เปรียบเทียบในสไลด์:** หอประชุม (main memory) มีนักศึกษา 100 คน (ข้อมูล) และ**ห้องอาจารย์มีเก้าอี้ 10 ตัว (cache)** เพื่อไม่ต้องเดินไปกลับหอประชุมบ่อย
:::

| คำศัพท์ | ความหมาย |
|---|---|
| **Hit** | หาข้อมูลเจอใน cache |
| **Hit rate (hit ratio)** | ความน่าจะเป็นที่หาเจอใน cache |
| **Hit time** | เวลาที่ใช้เข้าถึงข้อมูลใน cache |
| **Miss** | หาไม่เจอใน cache ต้องไปดึงจากระดับล่าง |
| **Miss rate** | **= 1 − hit rate** |
| **Miss penalty** | **เวลาที่ใช้นำข้อมูลเข้า cache** (เวลาเพิ่มเมื่อ miss) |
| **Block (line)** | ก้อนข้อมูลที่ย้ายเข้าออก cache **ทั้งก้อนเสมอ** |

::: key
**4 คำถามของ memory hierarchy** (ใช้ได้ทั้งกับ cache, TLB และ virtual memory):
1. **Placement:** block วางที่ไหนได้
2. **Identification:** หา block เจอได้อย่างไร (tag)
3. **Replacement:** ตอน miss จะเอา block ไหนออก
4. **Write strategy:** ตอนเขียนจะเกิดอะไรขึ้น
:::

## 8.5 Direct-Mapped Cache: Tag, Index, Offset

::: term
[Direct-mapped cache]{.abbr} [แคชแบบจับคู่ตรง]{.th}

- **คืออะไร:** **แต่ละ block ของ memory วางได้ที่เดียวใน cache** (มีเก้าอี้ประจำตัว)
- **ข้อดี:** ง่าย เร็ว ใช้ comparator ตัวเดียว
- **ข้อเสีย:** **conflict miss** (2 block ที่ index ตรงกันจะไล่กันออก)
:::

::: term
[Index]{.abbr} [ดัชนี (บอกว่าจะนั่งเก้าอี้ตัวไหน)]{.th}

- **คืออะไร:** ส่วนของ address ที่ใช้**เลือก line (หรือ set) ใน cache**
- **สูตร (ฐานสิบ):** **Index = (address mod cache size) div block size**
- **จำนวนบิต:** log₂(จำนวน lines) โดยจำนวน lines = cache size / block size (ถ้าเป็น set-associative ให้ใช้จำนวน sets)
:::

::: term
[Tag]{.abbr} [ป้ายชื่อ (บอกว่าใครนั่งอยู่บนเก้าอี้ตัวนั้น)]{.th}

- **คืออะไร:** ส่วนบนของ address ที่**เก็บไว้คู่กับข้อมูลใน cache** เพื่อตรวจว่า block ที่อยู่ใน line นั้นเป็น address ที่เราต้องการจริงไหม
- **สูตร (ฐานสิบ, direct-mapped):** **Tag = address div cache size**
- **การตรวจ hit:** **valid = 1 และ tag ที่เก็บไว้ = tag ของ address** (ใช้ comparator)
:::

::: term
[Offset (block offset + byte offset)]{.abbr} [ตำแหน่งภายใน block]{.th}

- **คืออะไร:** บิตล่างสุดของ address ที่บอกว่าต้องการ **byte (หรือ word) ไหนภายใน block**
- **จำนวนบิต:** log₂(block size เป็น byte)
- **การใช้งาน:** block offset เลือก word ใน block (ผ่าน MUX) และ byte offset เลือก byte ใน word
:::

::: term
[Valid bit / Dirty bit]{.abbr} [บิตบอกความถูกต้อง / บิตบอกว่าถูกแก้ไข]{.th}

- **Valid bit:** บอกว่า line นี้**มีข้อมูลที่ใช้ได้หรือยัง** (ตอนเปิดเครื่อง = 0 ทั้งหมด)
- **Dirty bit:** บอกว่า block นี้**ถูกเขียนแล้วแต่ยังไม่ได้เขียนกลับ memory** ใช้กับ **write-back** (ตอน replace ถ้า dirty = 1 ต้องเขียนกลับก่อน)
:::

::: formula
| Tag | Index | Block offset | Byte offset |

offset bits = log₂(block size B) · index bits = log₂(#sets) · tag bits = address bits − index − offset

#sets = cache size / (block size × associativity)
:::

::: ex
**เปรียบเทียบเก้าอี้:** cache size 10, block 1 → คนที่มี id 105 นั่ง **index 5** (105 mod 10) และติด **tag 10** (105 div 10)
:::

::: ex
**สไลด์: Tag [31:10], Index [9:2], Byte offset [1:0]**
- block = 4 bytes (1 word), 2⁸ = 256 lines → **cache = 1 KB**
- **ตำแหน่งของ 0x00004098:** offset 0, **index = (0x4098 >> 2) AND 0xFF = 0x26 = 38**, **tag = 0x4098 >> 10 = 0x10 = 16**

**สไลด์ (เพิ่ม spatial): Tag [31:12], Index [11:4], Block offset [3:2], Byte offset [1:0]**
- block = 4 words = **16 bytes**, 256 lines → **cache = 4 KB**
:::

## 8.6 Cache Performance

::: term
[AMAT]{.abbr} [Average Memory Access Time]{.full} [เวลาเข้าถึงหน่วยความจำเฉลี่ย]{.th}

- **สูตร:** **AMAT = Hit time + Miss rate × Miss penalty** (หน่วยมักเป็น cycle)
- **CPI เมื่อคิด cache:** **CPI = CPI<sub>ideal</sub> + (memory accesses ต่อคำสั่ง × miss rate × miss penalty)** (บทก่อน ๆ สมมติว่า memory ใช้ 1 cycle)
- **Multilevel:** AMAT₀ = Hit₀ + MR₀ × **MissPenalty₀** โดย **MissPenalty₀ = AMAT₁** = Hit₁ + MR₁ × MissPenalty₁
- **ลด AMAT ได้ 3 ทาง:** ลด hit time (**cache เล็ก**), ลด miss rate และลด miss penalty (**L2 cache**)
:::

::: ex
L1 hit 1 cycle, L1 miss 5%, L2 hit 10 cycles, L2 local miss 20% และ memory 100 cycles
- AMAT = 1 + 0.05 × (10 + 0.2 × 100) = 1 + 0.05 × 30 = **2.5 cycles**
- ถ้าไม่มี L2: 1 + 0.05 × 100 = 6 cycles
:::

## 8.7 Sources of Miss (3C)

::: term
[Compulsory miss / Cold miss]{.abbr} [miss ภาคบังคับ]{.th}

- **คืออะไร:** miss ตอน**เข้าถึง block ครั้งแรก** (cache ยังว่าง)
- **แก้:** ทำอะไรไม่ได้มาก แต่ **prefetch** และ block ใหญ่ขึ้นช่วยได้
:::

::: term
[Capacity miss]{.abbr} [miss จากความจุไม่พอ]{.th}

- **คืออะไร:** cache **เล็กเกินไปสำหรับ working set** ของโปรแกรม ทำให้ block ถูกไล่ออกก่อนจะได้ใช้อีก
- **กรณีสุดโต่ง:** **Ping-Pong effect** คือ cache มีแค่ 1 line ทุก address ใหม่จึง miss หมด (วางกระดาษบนโต๊ะได้ทีละแผ่น พอเปลี่ยนหน้าก็ miss)
- **แก้:** เพิ่ม cache size
:::

::: term
[Conflict miss]{.abbr} [miss จากการชนตำแหน่ง]{.th}

- **คืออะไร:** **cache ยังมีที่ว่าง แต่ mapping บังคับให้หลาย block แย่ง index เดียวกัน**
- **แก้:** (1) เพิ่ม cache size (2) **เพิ่ม associativity** (หลาย entry ต่อ index)
- **Fully associative มี conflict miss = 0**
:::

## 8.8 Cache Configurations (5 อย่าง)

1. **Cache size**
2. **Block size**
3. **Associativity**
4. **Replacement algorithm**
5. **Write management (write buffer)**

::: term
[Block size]{.abbr} [ขนาดบล็อก]{.th}

- **block ใหญ่ขึ้น:** spatial locality ดีขึ้น (ลด compulsory miss)
- **แต่:** **miss penalty สูงขึ้น** ("คนหลายคนเข้าห้องผ่านประตูเล็ก") เว้นแต่จะเพิ่มขนาด bus
- **ถ้าใหญ่เกินไป** (ที่ cache size คงที่): จำนวน block น้อยลง ทำให้ **temporal locality แย่ลงและ miss rate กลับเพิ่มขึ้น** (กราฟรูปตัว U)
- **วิธีหาค่าที่ดีที่สุด:** ต้อง benchmark (Assignment II)
:::

::: term
[Set-associative cache (n-way)]{.abbr} [แคชแบบเชื่อมโยงเป็นชุด]{.th}

- **คืออะไร:** แบ่ง cache เป็น **sets** โดยแต่ละ set มี **n lines (ways)** และ block วางได้ **ที่ใดก็ได้ใน set ของมัน**
- **ผลดี:** **ลด conflict miss** (มีเก้าอี้ 2 ชุดในห้อง)
- **ต้นทุน:** ต้องมี **n comparators + MUX ใหญ่** → **hit time อาจสูงขึ้น** และต้องมี replacement policy
- **กรณีพิเศษ:** **1-way = direct-mapped** และ **n = จำนวน lines = fully associative**
:::

::: term
[Fully associative cache]{.abbr} [แคชแบบเชื่อมโยงเต็มที่]{.th}

- **คืออะไร:** **ไม่มี index** block วางที่ไหนก็ได้
- **ผลดี:** **conflict miss = 0**
- **ต้นทุน:** ต้องมี **comparator เท่ากับจำนวน lines** (แพง) จึงเหมาะกับโครงสร้างเล็ก ๆ อย่าง TLB
:::

::: term
[Replacement algorithm]{.abbr} [นโยบายเลือก block ที่จะเอาออก]{.th}

- **LRU (Least Recently Used):** ทิ้ง block ที่**ไม่ได้ใช้นานที่สุด** (อาศัย temporal locality)
- **Round Robin:** ผลัดกันเอาออก
- **FIFO:** ทิ้ง block ที่เข้ามาก่อน
- **Random:** สุ่มเลือก
- **Direct-mapped ไม่ต้องมี replacement algorithm** เพราะมีที่วางได้ที่เดียว จึงต้องแทนที่ตัวเดิมเสมอ
- **ในทางปฏิบัติ:** **แยก I-cache กับ D-cache** (code มี spatial locality สูงกว่า)
:::

::: term
[L2 cache / Multilevel cache]{.abbr} [แคชระดับที่ 2]{.th}

- **คืออะไร:** cache ระดับที่สองซึ่งใหญ่กว่าแต่ช้ากว่า L1 แต่ยังเร็วกว่า memory มาก ("**เก้าอี้ที่โถงทางเดิน**")
- **ทำหน้าที่:** **ลด miss penalty** ของ L1 (miss L1 อาจไป hit ที่ L2) และ**แก้ปัญหา write buffer saturation**
:::

## 8.9 Write Management

::: term
[Write-back]{.abbr} [เขียนกลับภายหลัง]{.th}

- **คืออะไร:** เขียนลง **cache อย่างเดียว** แล้วตั้ง **dirty bit** จากนั้นจะ**เขียนลง memory ตอน block ถูก replace**
- **ข้อดี:** **เร็ว** และ**ดีกับการเขียนซ้ำ (repeated write)**
- **ข้อเสีย:** **ข้อมูล incoherent ในระบบ multiprocessor** (memory หรือ cache ของ CPU อื่นมีค่าเก่า)
:::

::: term
[Write-through]{.abbr} [เขียนผ่านทันที]{.th}

- **คืออะไร:** **เขียนทั้ง cache และ memory ทุกครั้ง**
- **ข้อดี:** memory เป็นปัจจุบันเสมอ จึง**เหมาะกับ multiprocessor**
- **ข้อเสีย:** **ช้า** และ**แย่กับ repeated write** (ทุกการเขียนช้าพอ ๆ กับ miss penalty)
- **สไลด์ใช้ write-through + write allocate** เพื่อความง่าย
:::

::: term
[Write allocate vs No-write allocate]{.abbr} [ตอน write miss จะโหลด block ไหม]{.th}

- **Write allocate:** ตอน write miss **โหลด block เข้า cache ก่อนแล้วเขียน** (ใช้เวลา = miss penalty + write time)
- **No-write allocate:** **เขียนตรงไประดับล่าง** โดยไม่โหลด block
- **นอกขอบเขต:** การเขียนแค่ส่วนหนึ่งของ block (subblock)
:::

::: term
[Write buffer]{.abbr} [บัฟเฟอร์การเขียน]{.th}

- **คืออะไร:** **FIFO เล็ก ๆ (เช่น 4 words)** ระหว่าง cache กับ memory ใช้กับ **write-through**
- **ทำหน้าที่:** CPU เขียนลง buffer แล้ว**ทำงานต่อได้ทันที** ส่วน buffer จะค่อย ๆ ทยอยเขียนลง memory ("**มีคนวิ่งไปบอกที่หอประชุมแทน**")
- **Saturation:** ถ้า**อัตราการเขียนสูงกว่าที่ memory รับไหว** buffer จะเต็ม**ไม่ว่าจะใหญ่แค่ไหน**
- **แก้:** **เพิ่ม L2 cache** (วิ่งไปแค่โถงทางเดิน)
:::

## 8.10 Software & Cache

- Cache **transparent** ต่อ software (ได้ประโยชน์โดยไม่ต้องแก้โค้ด) แต่ programmer ยังเขียนโค้ดให้ได้ locality ดีขึ้นได้
- **Temporal:** ใช้ตัวแปรใน scope ซ้ำต่อเนื่องกัน

::: term
[Row-major vs Column-major order]{.abbr} [การเรียงอาร์เรย์ 2 มิติแบบแถวหลัก vs คอลัมน์หลัก]{.th}

- **Row-major (ภาษา C):** เก็บ `data[0][0], data[0][1], …` ต่อกันทีละแถว
- **Column-major (Fortran):** เก็บทีละคอลัมน์
- **ผลต่อ cache:** ใน C **วน r ข้างนอก c ข้างใน** จะเข้าถึง memory แบบต่อเนื่อง (**spatial locality ดี**) จึงเร็วกว่าวน c ข้างนอก ซึ่งกระโดดข้ามทีละ 1 แถว
:::

::: ex
**ลด conflict miss ด้วย array of struct**
- `a[i], b[i], c[i]` จากสาม array ที่แยกกัน มักตกที่ **cache index เดียวกัน** (เมื่อขนาด array ลงตัวกับ cache) จึงไล่กันออก
- แปลงเป็น `struct {int a, b, c;} data[100]` ให้ `data[i].a/.b/.c` **อยู่ติดกันใน block เดียวกัน**
:::

## 8.11 Virtual Memory (Ch8 part 2)

::: term
[Virtual memory (VM)]{.abbr} [หน่วยความจำเสมือน]{.th}

- **คืออะไร:** กลไก (hardware + OS) ที่ให้แต่ละโปรแกรมเห็น **virtual address space ของตัวเอง** แล้วแปลงเป็น physical address
- **ทำหน้าที่ 3 อย่าง:**
  1. **Cost:** ทำให้เหมือนมี memory มากกว่าที่มีจริงด้วยการยืม disk (**รันโปรแกรมที่ต้องใช้ 4 GB บนเครื่อง 2 GB**) ผ่าน demand loading และ swap
  2. **Relocation:** แต่ละ process มี address space ของตัวเอง (0x100 ของ A ไม่ใช่ 0x100 ของ B)
  3. **Protection:** process A **เข้าถึง memory ของ B โดยตรงไม่ได้**
:::

::: term
[Virtual address (VA) / Physical address (PA)]{.abbr} [ที่อยู่เสมือน / ที่อยู่จริง]{.th}

- **VA:** address ที่ **software มองเห็น**
- **PA:** address จริงใน DRAM
- **การแปลง:** VA → PA ผ่าน **page table** (ซึ่ง TLB ช่วยให้เร็วขึ้น)
:::

::: term
[Page / Page frame]{.abbr} [หน้า (virtual) / กรอบหน้า (physical)]{.th}

- **Page:** block ของ virtual address space ขนาดเท่ากัน (เช่น **4 KB**) เทียบได้กับ block ใน cache
- **Page frame:** block ของ physical memory ขนาดเท่ากับ page
- **การแบ่ง address:** VA = **VPN (Virtual Page Number)** + **page offset** และ PA = **PPN/PFN (Physical Page/Frame Number)** + **page offset (เหมือนเดิม ไม่ถูกแปล)**
:::

::: term
[Page table]{.abbr} [ตารางหน้า]{.th}

- **คืออะไร:** ตารางที่ map **VPN → PPN** โดยแต่ละ entry (PTE) มี **valid bit**, PPN และ **access permission** (เช่น read-only)
- **ขอบเขต:** **มีหนึ่งตารางต่อ process** และมี **page table register** ชี้ไปที่ตารางของ process ปัจจุบัน
- **ขนาด:** **2^(VPN bits) × ขนาด PTE**
:::

::: term
[Page fault]{.abbr} [ข้อผิดพลาดหน้าไม่อยู่ในหน่วยความจำ]{.th}

- **คืออะไร:** **miss ของ virtual memory** คือ page ที่ต้องการไม่อยู่ใน physical memory (valid = 0) ต้องไปดึงจาก disk
- **ใครจัดการ:** **software (OS)** เพราะ hardware ไม่รู้จัก file system หรือ swap management
- **ต้นทุน:** **miss penalty มหาศาล** (เป็นล้าน cycles) จึงใช้ page ใหญ่ (4 KB) และ **ใช้ write-back เท่านั้น** (page out) เพราะ write-through ไปดิสก์แพงเกินไป
- **นโยบาย:** **demand load** (โหลดเมื่อเกิด fault) และ **replacement policy เป็นของ OS**
:::

::: term
[Swap space]{.abbr} [พื้นที่สลับบนดิสก์]{.th}

- **คืออะไร:** พื้นที่บน secondary storage ที่ยืมมาเก็บ page เมื่อ physical memory ไม่พอ
- **มุมมอง:** physical memory ทำหน้าที่เป็น **"cache" ของ disk**
:::

::: ex
**สไลด์:** VA 32 bits = **VPN 20 + offset 12** และ PA = **PPN 18 + offset 12**
- **Page size** = 2¹² = **4 KB**
- **Physical memory** = 2³⁰ = **1 GB**
- **Page table** = 2²⁰ × 4 B = **4 MB ต่อ process**
:::

::: term
[TLB]{.abbr} [Translation Lookaside Buffer]{.full} [บัฟเฟอร์จำผลการแปลงที่อยู่]{.th}

- **คืออะไร:** **cache ของ page table entries ที่เพิ่งใช้**
- **ทำไมต้องมี:** ทุกการเข้าถึง memory ต้องแปล VA → PA ถ้าต้องไปอ่าน page table ใน memory ทุกครั้งจะ**ช้าลงเท่าตัว**
- **คุณสมบัติ:**
  - เข้าถึงเร็วพอ ๆ กับ cache
  - **ขนาดเล็ก (ประมาณ 128–256 entries)** จึงทำเป็น **fully associative** ได้ (เครื่องระดับกลางใช้ small n-way)
- **ผลต่อ performance:** **TLB miss มีผลต่อ performance อย่างมีนัยสำคัญ**
- **สัมพันธ์กับ:** cache (overlapped access) และ context switch (ต้อง flush)
:::

## 8.12 Overlapped Cache & TLB Access

::: term
[Overlapped (VIPT) access]{.abbr} [เข้าถึง cache กับ TLB พร้อมกัน]{.th}

- **คืออะไร:** ใช้ **bits บนของ VA** เปิด TLB **พร้อมกับ**ใช้ **bits ล่าง (page offset ซึ่งไม่เปลี่ยนตอนแปล)** เป็น index ของ cache แล้วค่อยเทียบ tag ของ cache กับ PA ที่ได้จาก TLB
- **ทำหน้าที่:** ลดเวลา เพราะไม่ต้องรอแปล address เสร็จก่อนจึงเปิด cache
- **เงื่อนไข:** **index + offset ของ cache ต้องอยู่ในส่วน page offset** หรือก็คือ **cache size / associativity ≤ page size**
:::

```
IF cache hit AND (cache tag = PA)                    → ส่งข้อมูลให้ CPU
ELSE IF (cache miss OR tag ≠ PA) AND TLB hit          → อ่าน memory ด้วย PA จาก TLB
ELSE                                                 → แปล VA แบบปกติ (เดิน page table)
```

::: ex
**กรณีที่ทำไม่ได้:** cache 8 KB direct-mapped กับ page 4 KB
- cache ใช้ **13 bits** แต่ page offset มีแค่ **12 bits** (bit 12 เปลี่ยนตอนแปล)

**ทางแก้:**
1. ใช้ **page 8 KB**
2. ใช้ **2-way set associative** (เหลือ 4 KB ต่อ way)
3. ให้ **software รับประกันว่า VA[12] = PA[12]**

**Exercise: page 4 KB + cache 32 KB** → ต้องเป็น **8-way** (32/8 = 4 KB ต่อ way)
:::

::: term
[Virtually addressed cache]{.abbr} [แคชที่ใช้ virtual address]{.th}

- **คืออะไร:** เข้า cache ด้วย VA ก่อนแปล
- **ข้อดี:** เร็ว (ไม่ต้องรอ TLB)
- **ปัญหา:**
  - **shared memory / aliasing** (VA ต่างกันจากต่าง process map ไป PA เดียวกัน)
  - ต้องจัดการตอน context switch
:::

::: ex
**Process switch ต้องทำอะไร**
- **TLB:** **flush** (หรือติด ASID/PID ไว้ใน entry) เพราะ mapping เป็นของ process เก่า
- **Page table:** **ไม่ต้องลบ** แค่เปลี่ยน **page table register** ให้ชี้ไปที่ table ของ process ใหม่
- **Cache:** ถ้าเป็น **physically addressed** ไม่ต้อง flush ถ้าเป็น **virtually addressed** ต้อง flush หรือใส่ PID tag
:::

::: rel
**Cache vs Virtual Memory vs TLB** ใช้หลักเดียวกัน (4 คำถาม) แต่ต่างกันที่ขนาดและผู้จัดการ

| | Cache | TLB | Virtual memory |
|---|---|---|---|
| เป็น cache ของ | main memory | **page table** | **disk** |
| หน่วย | block (16–64 B) | PTE | page (4 KB) |
| Miss เรียกว่า | cache miss | TLB miss | **page fault** |
| จัดการ miss โดย | hardware | hardware (หรือ OS) | **OS (software)** |
| Placement | direct / n-way / fully | **fully assoc.** (เล็ก) | ที่ไหนก็ได้ (fully) |
| Write policy | write-back หรือ write-through | — | **write-back เท่านั้น** |

**นอกขอบเขต:** overlay, segmentation, inverted page table, multilevel page table, virtualized page table
:::

# Ch9: Storage Architecture

## 9.1 Storage และ Interface

::: term
[SSD / HDD]{.abbr} [Solid State Drive / Hard Disk Drive]{.full}

- **SSD:** เก็บข้อมูลบน **flash memory** ไม่มีชิ้นส่วนเคลื่อนไหว เร็ว
- **HDD:** **จานแม่เหล็กหมุน (mechanical)** ต้อง seek + rotate จึงเป็น semi-random access
:::

| Interface | ความเร็วในสไลด์ | ใช้ที่ |
|---|---|---|
| **SAS** (Serial Attached SCSI) | SAS-3 12 Gb/s | server |
| **SATA** (Serial ATA) | 3.0: 6 Gb/s | PC ทั่วไป |
| **PCIe** (PCI Express) | 3.0 x4: 31.5 Gb/s | NVMe SSD |
| **Fibre Channel** | 128 Gb/s | server, SAN |
| USB | 10 Gb/s | external |
| PATA (Parallel ATA) | 1064 Mb/s | รุ่นเก่า |
| Parallel SCSI | 40–2560 Mb/s | รุ่นเก่า |

::: trap
**Protocol/interface ≠ storage technology** (SSD อาจต่อผ่าน SATA หรือ PCIe ก็ได้)
:::

::: term
[Storage virtualization]{.abbr} [การจำลองพื้นที่จัดเก็บ]{.th}

- **คืออะไร:** "presenting a **logical view** of the physical storage" คือมองสื่อทุกชนิดเป็น **single pool** ได้ logical storage หนึ่ง (หรือหลาย) ก้อนจาก physical หลายก้อน
- **ตัวอย่าง:** RAID, JBOD, SAN
:::

## 9.2 RAID

::: term
[RAID]{.abbr} [Redundant Array of Independent (เดิมคือ Inexpensive) Disks]{.full} [ชุดดิสก์ที่มีความซ้ำซ้อน]{.th}

- **คืออะไร:** **storage virtualization** ที่รวมดิสก์หลายลูกเป็นลูกเดียวในมุมมองของระบบ
- **ผู้คิดค้น:** **David Patterson, Garth Gibson, Randy Katz (UC Berkeley, 1987)**
- **ทำไมต้องมี:** ยุค 60s–70s ดิสก์ที่เร็วต้องแพงมาก (เช่น RAM disk ที่มีแบตเตอรี่) RAID ทำให้**ดิสก์ราคาถูก (commodity) ได้ performance เทียบดิสก์แพง**
- **แต่ละ level** มีจุดสมดุลระหว่าง **reliability, availability, performance และ capacity** ต่างกัน
:::

| คำศัพท์ | ความหมาย |
|---|---|
| **Striping** | กระจายข้อมูลเป็นชิ้น ๆ ไปหลายดิสก์ อ่าน/เขียนขนานกัน → **เร็ว** |
| **Mirroring** | เก็บสำเนาเหมือนกันทุกบิตบนหลายดิสก์ → **ทนเสีย** |
| **Parity** | ข้อมูลตรวจสอบ (XOR) ที่ใช้**กู้ข้อมูลของดิสก์ที่เสีย**ได้ 1 ลูก |
| **Hamming code** | รหัสแก้ไขข้อผิดพลาดระดับบิต (ใช้ใน RAID 2) |

| Level | วิธี | Min disks | ทนเสียได้ | Capacity | จุดเด่น / ด้อย |
|---|---|---|---|---|---|
| **RAID 0** | **Stripe** | **2** | **0 ลูก** | N | **เร็วที่สุด แต่ reliability ต่ำ** (เสีย 1 ลูกข้อมูลหายหมด) |
| **RAID 1** | **Mirror** | **2** | 1 | N/2 | ดีเมื่อ **read และ reliability สำคัญ** |
| RAID 2 | **Bit-level** + **Hamming code** | — | 1 | — | **แทบไม่ใช้** |
| RAID 3 | **Byte-level** parity (ดิสก์เฉพาะ) | 3 | 1 | N − 1 | ดีกับ **long sequential read/write** แย่กับ random (แทบไม่ใช้) |
| RAID 4 | **Block-level** parity บน**ดิสก์เฉพาะ** | 3 | 1 | N − 1 | **read ดี write ช้า (parity disk เป็นคอขวด)** |
| **RAID 5** | Block-level parity **กระจายทุกดิสก์** | **3** | 1 | **N − 1** | **สมดุลระหว่าง performance กับ redundancy** |
| **RAID 6** | **2 parities** | **4** | **2** | **N − 2** | ทนเสียได้ 2 ลูก |

::: key
**ทำไม RAID 5 เร็วกว่า RAID 4:**
- RAID 4 ต้องเขียน parity ลง**ดิสก์ลูกเดียว**ทุกครั้งที่มีการเขียน ดิสก์ลูกนั้นจึงเป็น**คอขวด**
- RAID 5 **กระจาย parity ไปทุกดิสก์** การเขียนหลาย stripe จึงทำขนานกันได้
:::

::: term
[Nested RAID]{.abbr} [RAID ซ้อน]{.th}

- **RAID 01:** mirror ของ stripes
- **RAID 10:** stripe ของ mirrors
- **RAID 50:** stripe ของ RAID 5
:::

::: term
[JBOD / Span]{.abbr} [Just a Bunch Of Disks]{.full} [รวมดิสก์ต่อกันเฉย ๆ]{.th}

- **คืออะไร:** ต่อดิสก์หลายลูกให้เป็นก้อนเดียว (span) โดย**รวมดิสก์ที่ขนาดต่างกันได้**
- **ข้อจำกัด:** **ไม่มี redundancy** (ไม่ใช่ RAID)
:::

::: trap
**RAID ไม่ใช่ backup** เพราะไม่ป้องกันการลบไฟล์ผิด, ไวรัส หรือภัยที่ทำลายทุกดิสก์พร้อมกัน และ **RAID 0 ไม่มี redundancy เลย**
:::

## 9.3 Network Storage

::: term
[Block storage vs File storage vs Object storage]{.abbr} [การเก็บข้อมูลระดับบล็อก / ไฟล์ / ออบเจกต์]{.th}

- **Block:** ให้บริการเป็น **block/sector** ดิบ ๆ โดย **client สร้าง file system เอง** (เหมือนดิสก์เปล่า)
- **File:** ให้บริการเป็น **ไฟล์และโฟลเดอร์** โดย **server จัดการ file system และ permission**
- **Object:** เก็บเป็น object (ข้อมูล + metadata + ID) เข้าถึงผ่าน API เช่น Amazon S3
:::

::: term
[SAN]{.abbr} [Storage Area Network]{.full} [เครือข่ายพื้นที่จัดเก็บ]{.th}

- **คืออะไร:** **block storage ผ่าน network** (เช่น **iSCSI**)
- **ลักษณะ:**
  - มักต้องใช้ **hardware เฉพาะหรือ fiber**
  - **OS ของ client เห็นเป็น blocks/sectors และจัดการ file system เอง**
  - **มักให้ระบบเดียวใช้ (ไม่ share)**
- **เทคโนโลยีคล้ายกัน:** iATA, AoE (ไม่ค่อยนิยม)
:::

::: term
[NAS]{.abbr} [Network Attached Storage]{.full} [ที่เก็บข้อมูลต่อผ่านเครือข่าย]{.th}

- **คืออะไร:** **file storage ผ่าน network** ("network drive" เช่น map drive ใน Windows)
- **ลักษณะ:** **server จัดการ file system และ permission** และ **share ระหว่าง clients ได้ง่าย**
- **Protocols:**
  - **NFS** (Network File System)
  - **CIFS/SMB** (Common Internet File System / Server Message Block)
  - AFP (Apple Filing Protocol, deprecated)
  - FTP, SFTP
:::

::: term
[iSCSI]{.abbr} [Internet Small Computer System Interface]{.full}

- **คืออะไร:** ส่งคำสั่ง SCSI (block) ผ่านเครือข่าย IP ซึ่งเป็นวิธีหลักในการทำ SAN บน Ethernet
:::

| | **SAN** | **NAS** |
|---|---|---|
| ระดับ | **Block** | **File** |
| File system อยู่ที่ | **Client** | **Server** |
| Sharing | ไม่นิยม share | **share ง่าย** |
| Protocol | **iSCSI**, Fibre Channel | **NFS, CIFS/SMB** |
| Cloud | **Amazon EBS**, Google Persistent Disk | Google Cloud Filestore |

::: ex
**ประเภท storage ของ cloud (Exercise):**
- **Amazon S3 = object**
- **Amazon EBS = block**
- **Amazon DynamoDB = NoSQL key-value database** (ไม่ใช่ block หรือ file)
- **Google Cloud Storage bucket = object**
- **Google Drive, OneDrive, Dropbox, iCloud = file** (sync/share ไฟล์ ซึ่งภายในเก็บบน object storage)
:::

::: term
[Deduplication]{.abbr} [การกำจัดข้อมูลซ้ำ]{.th}

- **คืออะไร:** ระบบหลายระบบมักมีไฟล์หรือ block เหมือนกัน จึง**เก็บไว้ชุดเดียวแล้วชี้ร่วมกัน**เพื่อประหยัด physical space
:::

**Real-world considerations:** performance, price, block vs file vs object, sharing, reliability, redundancy, deduplication
