%TITLE Ch8 (2): Virtual Memory และ TLB
%CODE V
%REVIEW
- **ประโยชน์ 3 อย่าง:** (1) cost: รันโปรแกรม 4 GB บนเครื่อง 2 GB (ยืม disk, demand load, swap) (2) relocation: แต่ละ process มี address space ของตัวเอง (3) protection
- **Page** (virtual) / **page frame** (physical) · VA = **VPN** + offset · PA = **PPN** + offset (offset ไม่ถูกแปล)
- **Page table** map VPN → PPN มี valid bit และ permission · **มีต่อ process** · ขนาด = 2^(VPN bits) × PTE
- **Page fault** = miss ของ VM จัดการโดย **OS** (HW ไม่รู้จัก file system/swap) · miss penalty มหาศาล → page ใหญ่ (4 KB) และใช้ **write-back เท่านั้น**
- **TLB** = cache ของ page table entries · เล็ก (128–256 entries) จึงเป็น fully associative · TLB miss มีผลต่อ performance มาก
- **Overlapped cache & TLB:** ใช้ page offset เป็น index ของ cache พร้อมกับเปิด TLB → ต้องมี **cache size / ways ≤ page size**
- **Process switch:** flush TLB (หรือใช้ ASID) · page table ไม่ต้องลบ แค่เปลี่ยน page table register · cache แบบ physical ไม่ต้อง flush
- **Virtually addressed cache:** เร็วแต่มีปัญหา aliasing/shared memory
%ENDREVIEW
