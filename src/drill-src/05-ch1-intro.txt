%TITLE Ch1: Introduction (ISA vs Organization)
%CODE I
%REVIEW
- **ISA** = interface/สัญญาระหว่าง software กับ hardware กำหนด instructions, registers, addressing, format และ interrupt/exception ซึ่งเป็น abstraction ได้ 2 มุม: of machine for software และ **of software for hardware** (โปรแกรม 8088 ยังรันบน Core i7 ได้)
- **Organization** = โครงสร้างภายในที่ implement ISA: ALU, Control Unit, Register, Bus, Memory subsystem, I/O subsystem → **i3/i5/i7 ต่างกันที่ organization** (core, cache, Turbo Boost, Hyper-Threading)
- **ABI** = ข้อตกลงระดับ binary: calling convention, parameter passing, stack frame, alignment
- **Abstraction layers:** Application → OS/Compiler → **ISA** → Firmware → Processor/I/O → Datapath & Control → Digital design → Circuit → Layout
- **Trade-off หลัก:** Cost vs Performance (vs Power) ต้องใช้ modeling + measurement และออกแบบแบบ iterative
- **Trends:** Moore's Law (transistor ×2 ทุก ~2 ปี/18 เดือน, เป็นข้อสังเกต) · DRAM capacity ×4 ทุก 3 ปี · ราคา DRAM ลด 40% ต่อปี · software ใช้ memory ×2 ต่อปี
- **IBM 360 (1964)** รวม ISA 7 แบบ ทำให้ software portable
%ENDREVIEW

Moore's Law กล่าวว่า
a) clock rate เพิ่มเป็น 2 เท่าทุก 2 ปี
b) จำนวน transistor บน IC เพิ่มเป็น 2 เท่าประมาณทุก 2 ปี (18 เดือน)
c) ราคา DRAM ลดลง 40% ต่อปี
d) performance เพิ่มตามจำนวน core
=b
เป็นข้อสังเกตของ Gordon Moore เรื่องจำนวน transistor ไม่ได้พูดถึง clock หรือ performance

c) RISC vs CISC
d) Hardware vs Firmware
