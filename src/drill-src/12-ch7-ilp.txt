%REVIEW
- **Flynn:** SISD = uniprocessor · **SIMD** = vector/GPU (MMX, SSE, AVX, Altivec, CUDA) · **MISD** = fault-tolerant · **MIMD** = multicore/distributed
- **ILP** = จำนวนคำสั่งที่ทำพร้อมกันได้ · เทคนิค: vectorization, speculative execution, pipelining, superscalar (OoO, register renaming), VLIW

| แบบ | ILP | T(n) | ลดอะไร |
|---|---|---|---|
| Pipeline | k | (k + n − 1) T<sub>c</sub> | — |
| **Superscalar** (x) | kx | (k + (n − x)/x) T<sub>c</sub> | **CPI** = 1/x (dynamic, HW) |
| **Superpipeline** (m) | mk | (k + (n − 1)/m) T<sub>c</sub> | CPI = 1/m |
| **VLIW** (x) | kx | (k + (n/x − x)) T<sub>c</sub> | **IC** = n/x (static, compiler) |

- **SuperSymmetry:** degree เท่ากันได้ performance เท่ากัน
- Superscalar อาจทำงาน **out-of-order** → เสี่ยง **WAR/WAW** → แก้ด้วย **register renaming** หรือ in-order completion
- **VLIW:** static scheduling → binary ไม่ compatible ข้ามรุ่น (Itanium, EOL 2019)
- **Dynamic vs Static:** dynamic ทำให้ legacy code เร็วขึ้นโดยไม่ต้อง recompile แต่ HW ซับซ้อนและใช้ power มาก ส่วน static ใช้ HW ง่ายแต่ compiler ทำยาก → **dynamic ชนะ**
- **Loop unrolling:** basic block ใหญ่ขึ้น (8 → 3.5 cycles/iter, speedup 2.29) แลกกับ code ที่ใหญ่ขึ้นและถูกจำกัดด้วยจำนวน register · **software pipelining** unroll เท่าที่จำเป็น
- **SMT** = ดึงคำสั่งจากหลาย thread · Intel เรียก **Hyper-Threading**
%ENDREVIEW

%SA
(สไลด์) loop ปกติใช้ 8 cycles/iteration แต่หลัง unroll 4 รอบ + reschedule ใช้ 14 cycles ต่อ 4 iterations ได้ speedup เท่าใด และต้องทำอะไรเพิ่มเพื่อให้แต่ละ iteration อิสระกัน
=3.5 cycles/iter → speedup ≈ 2.29 · ต้อง register renaming
ถ้า unroll 5 รอบบน superscalar (Int + FP) จะได้ 12 cycles / 5 iter = 2.4 cycles/iter
%SA
(สไลด์) loop รวม 19 cycles โดยงาน integer ใช้ 7 cycles และ FP ใช้ 12 cycles ถ้ามี 2 pipelines (Int + FP) ทำงานพร้อมกัน speedup สูงสุดเท่าใด
=19/12 ≈ 1.6
CPU time = max(Int, FP) = 12 cycles
