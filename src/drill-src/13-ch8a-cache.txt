%TITLE Ch8 (1): Memory Hierarchy และ Cache
%CODE K
%REVIEW
- **Hierarchy:** register (SW จัดการ) → cache (HW) → memory → disk (HW + OS) · ระดับใกล้ CPU จะเล็ก เร็ว และแพง
- **DRAM** = capacitor, ถูก, ช้า, ต้อง refresh → main memory · **SRAM** = transistor, เร็ว, แพง → cache
- **Locality:** temporal (ใช้ซ้ำเร็ว ๆ นี้) · spatial (ใช้ข้อมูลที่อยู่ใกล้กัน)

::: formula
offset = log₂(block B) · #sets = cache size / (block × ways) · index = log₂(#sets) · tag = ที่เหลือ

ฐานสิบ (direct): index = (addr mod cache size) div block · tag = addr div cache size

AMAT = Hit time + Miss rate × Miss penalty · 2 ระดับ: H₁ + MR₁ × (H₂ + MR₂ × MP₂)

CPI = CPI<sub>ideal</sub> + Σ(accesses/instr × miss rate × penalty)
:::

- **3C:** compulsory (ครั้งแรก) · capacity (cache เล็กเกิน, ping-pong) · conflict (ยังมีที่ว่างแต่ชนกัน → แก้ด้วย associativity) · fully associative ไม่มี conflict miss
- **Block ใหญ่:** spatial ดีขึ้น แต่ miss penalty สูงขึ้น และถ้าใหญ่เกินไป miss rate กลับเพิ่ม · **associativity สูง:** conflict ลดลง แต่ hit time เพิ่ม (n comparators)
- **Replacement:** LRU, round robin, FIFO, random · direct-mapped ไม่ต้องมี replacement policy
- **Write-back** (dirty bit, เร็ว, incoherent ใน multiprocessor) vs **write-through** (ช้า, เหมาะกับ multiprocessor) · **write buffer** saturate → แก้ด้วย **L2**
- **Software:** C เป็น row-major → วน r ข้างนอก c ข้างใน · array of struct ช่วยลด conflict miss
%ENDREVIEW

%PART ข. Tag, Index, Offset
%MC
Direct-mapped cache ขนาด 64 bytes, block 8 bytes, address 300 (ฐานสิบ) อยู่ที่ index ใด
a) 4
b) 5
c) 37
d) 44
=b
(300 mod 64) div 8 = 44 div 8 = 5 (tag = 4)
%MC
2-way set associative ขนาด 8 KB, block 32 bytes มีกี่ sets
a) 64
b) 128
c) 256
d) 512
=b
8192 / (32 × 2) (256 คือจำนวน lines)
%PART ค. ตอบสั้น
%SA
(สไลด์) direct-mapped ที่มี Tag [31:10], Index [9:2], Byte offset [1:0] มี block size และ cache size เท่าใด และ address 0x00004098 อยู่ที่ index และ tag ใด
=block 4 B, cache 1 KB · index = 38, tag = 16
index = (0x4098 >> 2) AND 0xFF = 0x26 และ tag = 0x4098 >> 10 = 0x10
%SA
Direct-mapped 4 KB, block 16 B, address 32 bits จงหา index และ tag ของ 0x00001234
=index = 35, tag = 1 (offset = 4)
offset 4 bits, index 8 bits · 0x1234 = 0001 0010 0011 0100 → index = 0x23
%SA
Direct-mapped 16 KB, block 32 B: (ก) tag/index/offset กี่บิต (ข) tag/index/offset ของ 0x00012345 (ค) 0x00016345 ชนกับ 0x00012345 ไหม
=(ก) 18/9/5 (ข) tag 4, index 282, offset 5 (ค) ชน (conflict) เพราะ index เดียวกันแต่ tag = 5
0x16345 = 0x12345 + 16 KB (ขนาด cache พอดี) ถ้าเป็น 2-way ทั้งสองอยู่ด้วยกันได้
%SA
4-way set associative 64 KB, block 64 B, address 32 bits จงหาจำนวนบิตของ tag, index, offset
=tag 18, index 8, offset 6
#sets = 65536 / (64 × 4) = 256 (ถ้าลืมหาร ways จะได้ index 10 ซึ่งผิด)
%SA
2-way set associative 32 KB, block 32 B จงหาจำนวนบิตของ tag, index, offset และจำนวน comparator
=tag 18, index 9, offset 5, ใช้ 2 comparators
#sets = 32768 / 64 = 512
%SA
CPI<sub>ideal</sub> = 1, 30% เป็น load/store, I-miss 2%, D-miss 5%, penalty 100 cycles จงหา CPI จริง
=4.5
1 + 1 × 0.02 × 100 + 0.3 × 0.05 × 100 = 1 + 2 + 1.5 (ช้ากว่า perfect cache 4.5 เท่า)
%SA
CPI<sub>ideal</sub> = 1.2, 25% เป็น load/store, I-miss 1%, D-miss 4%, penalty 80 cycles จงหา CPI จริง
=2.8
1.2 + 0.8 + 0.8
%SA
L1 hit 1 cycle, miss 4% · L2 hit 12 cycles, local miss 25% · memory 200 cycles จงหา AMAT
=3.48 cycles
MP<sub>L1</sub> = 12 + 0.25 × 200 = 62 → 1 + 0.04 × 62 (ถ้าไม่มี L2 จะได้ 9 cycles)
%SA
แบบเดิม hit 2 cycles, miss 8%, penalty 50 · แบบ 2-way hit 2.5 cycles, miss 6% แบบใดดีกว่า
=เดิม 6 cycles, 2-way 5.5 cycles → 2-way ดีกว่า
ต้องคำนวณ AMAT เพราะ associativity แลก hit time กับ miss rate
%SA
(สไลด์) memory op ใช้ 50 cycles, op อื่น 1 cycle และมี memory op 10% CPU รอ memory กี่เปอร์เซ็นต์ของเวลา
=≈ 85%
(0.1 × 50) / (0.9 + 5) = 5/5.9 ซึ่งเป็นแรงจูงใจให้ต้องมี cache
