%TITLE Ch5: Multiple Cycle Processor
%CODE M
%REVIEW
- **ปัญหาของ single cycle:** cycle ยาว ทุกคำสั่งต้องรอเท่าคำสั่งที่ช้าที่สุด
- **วิธีแก้:** แบ่ง datapath แล้วใส่ intermediate registers (IR, REG_A, REG_B, REG_S, REG_M, REG_WR) ให้แต่ละส่วน**ใช้เวลาเท่า ๆ กัน** และคำสั่งง่ายข้ามขั้นที่ไม่ใช้ได้ ใช้ hardware ร่วมกันได้ (ALU คำนวณ PC + 4, รวม memory)
- **5 ขั้น:** Fetch (IR ← MEM[PC]; PC ← PC + 4) → Decode → Execute → Memory → Write back
- **จำนวน cycle: LW 5 · ORI/ORUI/ADD/SW 4 · BEQ/JMP 3** (BEQ บวกแค่ imm × 4 เพราะ PC + 4 ไปแล้วตอน fetch)
- **SW:** 1 Fetch · 2 A ← R[rs], B ← sign_ext, **M ← R[rt]** · 3 S ← A + B · 4 **MEM[S] ← M**
- **Control = FSM** (Fetch → Decode → ALU_Exec/ADD_Calc/BEQ/JMP → ...) implement ด้วย sequential circuit หรือ **microprogram** (เปลี่ยน Map ROM แล้วทำ ISA อื่นได้)
- **Multi-cycle ไม่ได้เร็วกว่าเสมอ:** เทียบ CPI<sub>avg</sub> × T<sub>c,multi</sub> กับ T<sub>c,single</sub>
%ENDREVIEW

%PART ค. ตอบสั้น
%SA
(Exercise ในสไลด์) single cycle 210 ns และ multi-cycle 45 ns CPI เฉลี่ยต้องไม่เกินเท่าใดจึงจะได้ performance อย่างน้อยเท่าเดิม
=CPI ≤ 4.67
210 / 45 = 4.67
%SA
(Exercise ในสไลด์) cycle time 40 ns โค้ด: `LW; LW; BEQ (not taken); ADD; SW` ใช้เวลาเท่าใด
=21 cycles = 840 ns
5 + 5 + 3 + 4 + 4 = 21
%SA
Single 200 ns, multi 50 ns และ mix: LW 20%, SW 10%, R-type/ORI 50%, BEQ 20% จงหา CPI และบอกว่าเครื่องใดเร็วกว่า
=CPI = 4.0, เร็วเท่ากัน (200 ns ต่อคำสั่ง)
0.2(5) + 0.1(4) + 0.5(4) + 0.2(3) = 4.0 → 4.0 × 50 = 200 ns
%SA
Single 250 ns, multi 60 ns และ mix: LW 25%, SW 10%, R/ORI 45%, BEQ 15%, JMP 5% จงหา CPI และบอกว่าเครื่องใดเร็วกว่า
=CPI = 4.05, multi เร็วกว่าเล็กน้อย (243 vs 250 ns)
1.25 + 0.40 + 1.80 + 0.45 + 0.15 = 4.05 → 4.05 × 60 = 243 ns · speedup ≈ 1.03
%SA
(ตัวอย่างในสไลด์) 100 คำสั่ง: single cycle 45 ns/cycle และ multi-cycle 10 ns/cycle CPI 4.6 แบบใดเร็วกว่า
=single 4500 ns, multi 4600 ns → single เร็วกว่า
แสดงว่า multi-cycle ไม่ได้เร็วกว่าเสมอ (pipeline ในตัวอย่างเดียวกันใช้ 1030 ns)
%SA
จะดัดแปลง datapath ให้ ALU ใช้คำนวณ PC + 4 แทน adder แยกได้อย่างไร
=ใส่ MUX ที่ input A (เลือก PC หรือ REG_A) และ input B (เลือก 4, REG_B หรือ imm × 4) แล้วใช้ ALU ใน cycle Fetch
ทำได้เพราะ Fetch ไม่ได้ใช้ ALU ทำอย่างอื่น
