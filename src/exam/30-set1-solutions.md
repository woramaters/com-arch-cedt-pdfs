## Part 1: Choice (อธิบายรายข้อ)

### Digital Logic

::: sol
**1. ตอบ [b) 11.25]{.ans}**

(1011.01)₂ = 1·8 + 0·4 + 1·2 + 1·1 + 0·½ + 1·¼ = 8 + 2 + 1 + 0.25 = **11.25**

- **ตัวลวง a:** อ่านตัวเลขหลังจุดเป็นฐานสิบตรง ๆ
- **ตัวลวง c:** คิดบิตหลังจุดผิดตำแหน่ง (0.1₂ = 0.5 แต่ 0.01₂ = 0.25)
- **หลักที่ใช้:** หลังจุดทศนิยม ค่าประจำหลักคือ 2⁻¹, 2⁻², …
:::

::: sol
**2. ตอบ [a) 1767₈]{.ans}**

0x3F7 = 0011 1111 0111 (หลักละ 4 บิต) แล้วจัดใหม่ทีละ 3 บิตจากขวาเป็น 001 111 110 111 = 1 7 6 7

- **ตรวจ:** 1·512 + 7·64 + 6·8 + 7 = 1015 และ 0x3F7 = 3·256 + 15·16 + 7 = 1015 ✓
- **ตัวลวง b:** แปลง "3" เป็นหลักแรกตรง ๆ (ลืมว่าต้องจัดกลุ่มใหม่ทั้งหมด)
:::

::: sol
**3. ตอบ [d) 0x9C]{.ans}**

1. +100 = 0110 0100
2. กลับทุกบิตได้ 1001 1011 (= 0x9B ซึ่งเป็น **1's complement**: ตัวลวง c)
3. บวก 1 ได้ **1001 1100 = 0x9C**

- **ตรวจ:** 0x9C = 156 และ 156 − 256 = −100 ✓
- **ตัวลวง b (0xE4):** แค่เปลี่ยน sign bit แบบ sign-magnitude
:::

::: sol
**4. ตอบ [b) −32 ถึง 31]{.ans}**

2's complement n bits มีช่วง −2ⁿ⁻¹ ถึง 2ⁿ⁻¹ − 1 → n = 6: **−32 ถึง 31**

- **ตัวลวง a:** เป็นช่วงของ sign-magnitude และ 1's complement
- **ตัวลวง d:** เป็นช่วงของ unsigned
- ช่วงของ 2's complement **ไม่สมมาตร** (ฝั่งลบมีมากกว่า 1 ค่า เพราะมีศูนย์ตัวเดียว)
:::

::: sol
**5. ตอบ [c) carry out = 0, overflow = 1]{.ans}**

0111 0000 + 0101 0000 = **1100 0000** (ไม่มีบิตทดออกจาก MSB → carry = 0)

- แต่ **บวก + บวก ได้ผลที่ MSB = 1 (ลบ)** → **signed overflow** (112 + 80 = 192 เกิน 127)
- ตรวจด้วยสูตร overflow = C<sub>in,MSB</sub> ⊕ C<sub>out,MSB</sub> = 1 ⊕ 0 = 1
- **หลัก:** carry มีความหมายกับ unsigned ส่วน overflow มีความหมายกับ signed ทั้งสองเป็นอิสระต่อกัน
:::

::: sol
**6. ตอบ [c) (AB)' = A' + B']{.ans}**

DeMorgan: กลับทุกตัวแปรแล้วสลับ AND ↔ OR → (AB)' = A' + B' และ (A + B)' = A'B'

- ตัวเลือก a, b เป็นความผิดพลาดที่พบบ่อย (กลับตัวแปรแต่ลืมสลับเครื่องหมาย)
- ตัวเลือก d ลืมกลับตัวแปร
:::

::: sol
**7. ตอบ [b) B']{.ans}**

พจน์ทั้ง 4 คือ minterm 000, 001, 100, 101 = m(0,1,4,5) ซึ่ง**ทุกตัวมี B = 0** ส่วน A และ C เปลี่ยนครบทุกค่า

- จัดกลุ่มเชิงพีชคณิต: A'B'(C' + C) + AB'(C' + C) = A'B' + AB' = B'(A' + A) = **B'**
- ใน K-map ทั้ง 4 ช่องอยู่ในคอลัมน์ B = 0 เป็นกลุ่มเดียว
:::

::: sol
**8. ตอบ [c) B']{.ans}**

- m(0,2,8,10) อยู่ที่ **มุมทั้งสี่** ของ K-map (A'B'C'D', A'B'CD', AB'C'D', AB'CD') ถ้าไม่มี don't care จะได้ B'D' (ตัวลวง a ซึ่งถูกแต่ยังไม่ minimal)
- เมื่อนับ d(1,3,9,11) เป็น 1 จะได้ 8 ช่องที่ B = 0 ทั้งหมด (แถว AB = 00 และ 10) → กลุ่ม 8 ช่อง = **B'** ซึ่งสั้นที่สุด
- **หลัก:** ใช้ don't care **เมื่อทำให้กลุ่มใหญ่ขึ้น**
:::

::: sol
**9. ตอบ [b) 5]{.ans}**

MUX 2ⁿ-to-1 มี select n เส้น → 32 = 2⁵ ได้ **5 เส้น**

- **ตัวลวง d (32):** นับจำนวน data input แทน select
:::

::: sol
**10. ตอบ [d) toggle]{.ans}**

Q⁺ = JQ' + K'Q → J = K = 1 ได้ Q⁺ = Q' (**กลับค่า**)

- ตารางของ JK: 00 = hold, 01 = reset, 10 = set, **11 = toggle**
- **กับดัก:** สถานะต้องห้าม (S = R = 1) เป็นของ **SR latch** ไม่ใช่ JK
:::

::: sol

**Moore:** output ขึ้นกับ **current state อย่างเดียว** (เขียน output ไว้ในวงกลม state)

## Part 2: ตอบสั้น (เฉลยละเอียด + เกณฑ์ 2 คะแนน)

::: sol
**S1. Full adder**

- [**Sum = A ⊕ B ⊕ Cin**]{.ans} (1 คะแนน)
- [**Cout = AB + Cin(A ⊕ B)**]{.ans} หรือเขียนแบบ majority function = AB + ACin + BCin (1 คะแนน)

**ที่มา:** Sum เป็น 1 เมื่อจำนวน 1 ในอินพุตเป็นเลขคี่ (XOR) ส่วน carry เกิดเมื่อ A, B เป็น 1 ทั้งคู่ (generate) หรือเมื่อมีตัวใดตัวหนึ่งเป็น 1 แล้ว Cin = 1 (propagate)
:::

::: sol
**S2. Moore "101" overlapping → [4 states, 2 flip-flops]{.ans}**

| State | ความหมาย | input 0 → | input 1 → | output |
|---|---|---|---|---|
| S0 | ยังไม่เห็นอะไร | S0 | S1 | 0 |
| S1 | เห็น "1" | S2 | S1 | 0 |
| S2 | เห็น "10" | S0 | S3 | 0 |
| S3 | เห็น "101" | S2 | S1 | **1** |

- จาก S3 ได้ 0 ไป S2 (เพราะ "1" ตัวท้ายใช้ซ้ำได้ แล้วตามด้วย 0 = "10") และได้ 1 ไป S1
- **FF ขั้นต่ำ = ⌈log₂4⌉ = 2** (ถ้าเป็น Mealy จะใช้แค่ 3 states)
- **เกณฑ์:** จำนวน state 1 คะแนน และจำนวน FF 1 คะแนน
:::

::: sol
**S3. [CPI = 2.3, CPU time = 2.3 s]{.ans}**

1. CPI = 0.4(1) + 0.3(4) + 0.1(3) + 0.2(2) = 0.4 + 1.2 + 0.3 + 0.4 = **2.3** (1 คะแนน)
2. CPU time = 2 × 10⁹ × 2.3 / (2 × 10⁹) = **2.3 s** (1 คะแนน)

ข้อสังเกต: load มี 30% ของคำสั่งแต่กินเวลา 1.2/2.3 = 52% ถ้าจะปรับปรุง ควรเริ่มที่ load (make the common case fast)
:::

::: sol
**S4. [n = 9 เท่า]{.ans}**

1. 1 / (0.1 + 0.9/n) = 5
2. → 0.1 + 0.9/n = 0.2
3. → 0.9/n = 0.1
4. → **n = 9**

ข้อสังเกต: speedup สูงสุดที่เป็นไปได้คือ 1/0.1 = 10 เท่านั้น ต้องเร่งถึง 9 เท่าเพื่อได้แค่ 5 (diminishing returns)
:::

::: sol
**S5. [d เริ่มที่ 16 และไบต์สุดท้ายคือ 24]{.ans}**

| ตัวแปร | ขนาด | ต้องหารลงตัวด้วย | วางที่ |
|---|---|---|---|
| a (char) | 1 | 1 | 0 |
| b (int) | 4 | 4 | 4–7 (pad 1–3) |
| c (short) | 2 | 2 | 8–9 |
| d (double) | 8 | 8 | **16–23** (pad 10–15) |
| e (char) | 1 | 1 | **24** |

รวมใช้ 25 bytes (ถ้าเป็น struct ใน C จะมี padding ท้ายให้ครบพหุคูณของ 8 รวมเป็น 32 bytes)
:::

::: sol
**S6. [CPI = 4.0, เร็วเท่ากัน]{.ans}**

1. CPI = 0.2(5) + 0.1(4) + 0.5(4) + 0.2(3) = 1.0 + 0.4 + 2.0 + 0.6 = **4.0** (1 คะแนน)
2. เวลาต่อคำสั่ง: multi = 4.0 × 50 = **200 ns** และ single = 200 ns → **เร็วเท่ากัน** speedup = 1.0 (1 คะแนน)

**บทเรียน:** multi-cycle ไม่ได้เร็วกว่าเสมอ ต้องคิด CPI ถ่วงด้วย instruction mix ทุกครั้ง
:::

::: sol
**S7. Dependencies + [stall 1 cycle]{.ans}**

| คู่ | Register | ชนิด | ปัญหาจริงใน 5-stage in-order ไหม |
|---|---|---|---|
| 1 → 2 | r1 | **RAW (load-use)** | **ใช่ ต้อง stall 1 cycle** |
| 2 → 3 | r3 | **RAW** | forwarding แก้ได้ |
| 2 → 4 | r1 | **WAR** | ไม่เป็นปัญหา (ADD#2 อ่านที่ ID ก่อนที่ #4 จะเขียนที่ WB เสมอ) |
| 1 → 4 | r1 | **WAW** | ไม่เป็นปัญหา (WB เกิดตามลำดับ) |

- เวลารวม = (5 + 4 − 1) + 1 = **9 cycles**
- **เกณฑ์:** ระบุ dependency ครบ 1 คะแนน และตอบ stall = 1 ได้ 1 คะแนน
:::

::: sol
**S8. RAID 5 vs RAID 4 + [อย่างน้อย 3 ลูก]{.ans}**

- **RAID 4** เก็บ parity บน**ดิสก์เฉพาะลูกเดียว** การเขียนทุกครั้งต้องอัปเดตดิสก์นั้น จึงเป็น**คอขวด**
- **RAID 5** **กระจาย parity ไปทุกดิสก์** การเขียนที่ไปคนละ stripe จึงอัปเดต parity คนละดิสก์พร้อมกันได้ (1 คะแนน)
- ต้องมีดิสก์อย่างน้อย **3 ลูก** (ข้อมูล 2 + parity 1) (1 คะแนน)
:::

::: sol
**S9. [tag 18, index 8, offset 6]{.ans}**

1. offset = log₂64 = **6 bits**
2. #sets = 64 KB / (64 B × 4 ways) = 65536 / 256 = **256 sets** → index = log₂256 = **8 bits**
3. tag = 32 − 8 − 6 = **18 bits**

- **กับดัก:** ถ้าลืมหารด้วย 4 ways จะได้ 1024 lines → index 10 และ tag 16 (ผิด)
- **เกณฑ์:** ถูก 3 ค่าได้ 2 คะแนน ถูก 2 ค่าได้ 1 คะแนน
:::

::: sol
**S10. [AMAT = 3.48 cycles]{.ans}**

1. Miss penalty ของ L1 = AMAT ของ L2 = 12 + 0.25 × 200 = 12 + 50 = **62 cycles** (1 คะแนน)
2. AMAT = 1 + 0.04 × 62 = 1 + 2.48 = **3.48 cycles** (1 คะแนน)

เทียบกับไม่มี L2: 1 + 0.04 × 200 = 9 cycles → L2 ลด AMAT ได้มากกว่า 2.5 เท่า
:::
